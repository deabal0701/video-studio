# 영상 제작 기록 — 형식 규약

**이 파일은 스킬이 들고 다니는 형식 정의다.** 프로젝트 쪽(`.claude/memory/README.md`)에 사본을
두지 않는다 — 두면 갈라지고, 스킬만 옮긴 프로젝트에서는 아예 없다.

**영상 한 편이 파일 하나다.** 기록은 프로젝트의 `.claude/memory/<영상 id>.md` 에 쓰고,
id 는 `out/<영상 id>/`와 같게 맞춘다. `out/`은 산출물(mp4·캐시)이고, 여기는 **어떻게 만들었고
결과가 어땠는지**를 남긴다. `out/`은 용량 때문에 지워질 수 있지만 기록은 남는다.

```
.claude/memory/
  <영상 id>.md        제작 기록 + 평가 점수      ← 이 형식으로 쓴다
```

## 언제 쓰나

- **제작 직후** — SKILL.md `8. 재생·보고·기록` 단계에서 `## 평가`를 뺀 전부를 채운다.
- **평가 후** — 9단계 평가 agent가 같은 파일의 `## 평가` 절과 `score:` 를 채운다. 사람이 쓰지 않는다.

## 형식

```markdown
---
id: hangang
title: 한강 소개 쇼츠
date: 2026-08-08
status: draft | done
variants: [9x16]
duration: 62s
voice: ElevenLabs / <목소리 이름>
scenes: tools/video/scenes.hangang.json
score: null            # 평가 전 null. 평가 agent가 채운다
---

## 제작

무엇을 만들었고 어떤 선택을 했는지. 특히 **왜 그렇게 했는지** — 대본 톤, 목소리를 고른 이유,
모션을 새로 만들었다면 그 이유.

## 소재

BGM·사진·B롤의 출처와 라이선스. 나중에 재사용하거나 문제가 생겼을 때 추적할 수 있어야 한다.

## 걸린 것

만들면서 막힌 지점과 해결 방법. 셀렉터가 안 맞았다거나, TTS 발음이 틀렸다거나,
드리프트가 났다거나. **다음 영상에서 같은 데 걸리지 않으려고 적는다.**

## 남은 것

미확정 사항 — 카피 확정, BGM 교체 예정, 도메인 등.

## 평가

<!-- 평가 agent가 채운다. 사람이 직접 쓰지 않는다. -->
```

## 규칙

- **id는 `out/<id>/`와 반드시 일치시킨다.** 기록과 산출물을 잇는 유일한 열쇠다.
- **제작 중에 적는다.** 끝나고 몰아 쓰면 "걸린 것"이 가장 먼저 날아간다 — 그게 제일 값지다.
- **재촬영·재합성해도 파일은 하나로 유지한다.** 이력은 git이 남긴다.
- **`score`는 평가 agent만 쓴다.** 자평하지 않는다.
