# 09 — 화면 점검 SSOT (UI/UX 개선 대장)

> **이 문서는 "화면을 하나하나 보고 고치는" 작업의 정본이다.** 화면마다 ① 지금 어떤지
> ② 무엇이 문제인지 ③ 어떻게 고쳤는지 ④ 상태를 한 곳에 모은다.
>
> 역할 경계: **무엇을 담는가** = [03_screens](03_screens.md) · **어떻게 그리는가(스타일 규칙)**
> = [08_qt-style](08_qt-style.md) · **지금 어떤 상태이고 무엇을 고칠 것인가** = 이 문서.

## 점검 루프 (1화면 = 1사이클)

```
1. 캡처   conda run -n penv3.13-insait python packaging\capture-screens.py
          → docs\ui-shots\NN-화면.png (같은 이름으로 덮어써 전/후가 대조된다)
2. 점검   아래 "공통 점검 항목" 8개 + 그 화면의 고유 항목을 눈으로 확인
3. 수정   app/pages/*.py · app/theme.py
4. 재캡처 → 같은 화면 카드의 상태를 갱신
```

**추정 금지 — 화면은 반드시 캡처를 눈으로 본다.** 다만 **캡처 자체도 의심한다.** 2026-08-22
하루에 두 번 속았다:

| 증상 | 실제 원인 | 대책 |
|---|---|---|
| 대시보드가 빈 화면으로 찍힘 | 조건 충족 직후 = 배치·페인트 전 | `shot()` 이 항상 `pump(0.8)` 후 찍는다 |
| 첫 실행 위저드 자리에 설정 화면이 찍힘 | `shot("14-first-run")` 에 **위젯 인자 누락** → 뒤의 메인 창을 잡음 | 모달·다이얼로그는 `shot(name, widget)` 필수 |

**같은 그림이 두 장이면 캡처를 먼저 의심한다.** 화면을 고치기 전에 캡처가 그 화면인지 본다.

## 공통 점검 항목 (모든 화면)

| # | 항목 | 판정 기준 |
|---|---|---|
| G1 | **빈 화면이 없는가** | 데이터가 있는데 비어 보이면 즉시 결함. 데이터가 없으면 **빈 상태 안내**(무엇을 하면 되는지)를 보여준다 |
| G2 | **폭을 쓰는가** | 콘텐츠가 좌측 1/3 에 몰리고 오른쪽이 비어 있지 않은가. 표·리스트는 남는 폭을 채운다 |
| G3 | **밀도가 맞는가** | 한 화면에 필요한 정보가 스크롤 없이 보이는가. 카드 높이·여백이 과하지 않은가 |
| G4 | **아이콘이 의도대로 보이는가** | 이모지는 OS 폰트에 따라 **다른 그림**으로 나온다 (⬜→체크박스, 🔄→END 화살표 실측). 의미를 이모지에 싣지 않는다 |
| G5 | **중복이 없는가** | 같은 정보를 두 번 보여주지 않는가 (레인 제목 + 카드 칩) |
| G6 | **개발 문구가 없는가** | "5-4 에서 열립니다" 같은 내부 일정·단계 번호가 사용자에게 보이면 안 된다 |
| G7 | **원문 노출이 없는가** | 마크다운 기호(`**`, 백틱)·경로 문자열이 날것으로 보이지 않는가 |
| G8 | **다음 행동이 분명한가** | 이 화면에서 무엇을 해야 하는지 버튼·문구로 드러나는가 |
