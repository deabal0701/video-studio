# 00 — 개요 · 원칙 · 확정 결정

## 무엇을 만드나

**강좌(시리즈) 영상 제작 스튜디오.** 사용자가 화면에서 강좌를 개설하고(목소리·색·워터마크·BGM),
회차 대본을 쓰거나 AI로 초안을 받아 다듬고, 버튼 하나로 빌드해, 프레임 검수와 유튜브
업로드 준비물(제목·설명·챕터·자막·썸네일)까지 받아 가는 앱.

**배포 형태 (2026-08-21 전환 — D12): 로컬 단독 설치형 Windows 데스크톱 앱.**
담당자 PC 에 설치기 하나로 배포하고 `VideoStudio.exe` 하나만 실행한다 — 상세는
[07_desktop.md](07_desktop.md). 1~4단계는 웹(Vue+FastAPI) 콘솔로 구현·검증을 마쳤고,
5단계에서 같은 core 위의 PySide6 앱으로 껍데기를 교체한다.

내부 도구로 시작해 **상용 서비스**(다수 사용자·요금제)로 키운다는 방향은 유지 — 그래서
처음부터 "나중에 바꾸기 비싼 것"(스토리지 추상화·잡 큐·라이선스)을 맞춰 둔다.

| 에이전트 PoC | video-agent/agent.mjs 173줄 (Claude Agent SDK) | 동작 확인. 단발 실행·상태 없음 |

렌더링이 아니라 그 앞뒤 — 편집 UI·검증의 입력시점 강제·작업 큐·검수 UI·산출물 정리다.

## 문제 정의 — 현재 CLI 방식의 실제 고통

| # | 고통 | 앱의 해법 |
|---|---|---|
| 1 | 한 편에 수십 분 굽고, 결함 대부분이 **오류 없이 조용히** 발생 (없는 params 는 지워지고, 틀린 경로는 검은 화면, 긴 B롤은 정지 프레임) | 사전점검을 "빌드 전 검사"에서 **"입력 시점 강제"** 로 끌어올린다 — 틀린 입력이 불가능한 폼 |
| 2 | 상대경로 기준이 한 파일 안에 3종 이상 (실제 대본에 "셋 다 기준이 달라 실측으로 확정했다" 주석) | 파일 피커 + **경로 자동 계산.** 사람이 경로 문자열을 만지지 않는다 |
| 3 | 분량 예산(1,850자)·강좌 일관성(voice/render 대조)·프레임 검수가 전부 수동 | 실시간 게이지 · 저장 시 자동 대조 · 프레임 그리드 자동 추출 |
| 4 | 강좌 상태(어느 회차가 어디까지 갔나)·유튜브 준비물이 파일 여기저기 흩어짐 | 커리큘럼 보드 · 배포 산출물 화면 |

실측 사례: hr-basics-01 은 클립 16개·내레이션 2,074자로 **예산(1,850자) 12% 초과** 상태였다.
CLI 에서는 굽고 나서야 아는 것을 화면은 입력 중에 보여 준다.

## 제품 원칙

1. **파일이 SSOT다.** `projects/<id>/` 폴더(course.json·scenes.json·plan.md·facts.md)가
   정본이고 DB 를 두지 않는다. 산출물(`out/`)은 언제든 재생성 가능한 파생물이다.
   → 앱 밖에서(에디터·Claude Code) 고쳐도 앱이 그대로 본다. 진실이 갈라지지 않는다.
2. **결정적/확률적을 가른다.** 편집·검증·빌드·검수 = 결정적 코드(키 불요).
   대본 초안·도식 생성·평가 = 에이전트(키 필요, 선택 기능). 앱은 에이전트 없이 완결 동작한다.
3. **제작 규약의 정본은 스킬 문서다.** SKILL.md 의 규칙(분량·골격·도식 규칙·검증)을 코드로
   복제하지 않고, 기계화할 수 있는 것(글자수·경로·params·일관성)만 검증기로 만든다.
   에이전트는 스킬 문서를 그대로 읽는다.
4. **엔진은 손대지 않는다.** Node CLI 는 vendoring 하고 subprocess 로 부른다. 앱 사정으로
   엔진을 고치면 스킬 규약과 어긋난다(실제로 tools/video 가 스킬보다 낡아 preflight 가 빠진
   사고가 있었다 — 동기화 규칙은 01 문서).
5. **되돌리기 싼 것은 묻지 않고, 비싼 것은 입력 전에 잡는다.** 스킬의 철학 그대로 UI 에 적용 —
   자막 색은 나중에 바꾸면 되지만, 목소리·경로·분량은 입력 시점에 맞춘다.
