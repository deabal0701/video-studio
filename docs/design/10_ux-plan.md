## 새 정보 구조 — 번호의 재정의

**진단**: ①②③(프로젝트)과 ④⑤⑥⑦(영상)이 하나의 번호 체계처럼 보이는데,
①②③은 **순서가 아니다**(설정·목록·킷은 단계가 아님). 순서인 것은 영상 안의 4단계뿐.

```
대시보드
└─ 프로젝트         [영상 목록]  [설정]  [브랜드 킷]     ← 번호 없음 (순서 아님)
   └─ 영상          ① 구성  ② 대본  ③ 검수  ④ 배포      ← 번호는 여기만 (진짜 순서)
```

- 프로젝트 탭: **영상 목록이 첫 탭·기본 탭** (주인공), 번호 제거
- 영상 탭: ④⑤⑥⑦ → **①②③④ 재부여** — "①부터 하면 된다"가 화면에서 읽힌다

**추가 지적 11 (2026-08-23) — 창 상단을 무엇으로 채우나 ✅ 구현**

> "메뉴를 타이틀바 상단에 붙이는 것은 어떤가. 제목표시줄과 약간의 공백이 있다.
> 다른 것을 채워 넣을 수 있나?" · "상단 타이틀바와는 차이가 있어야 한다"

| 안 | 판정 | 근거 |
|---|---|---|
| **A. 메뉴를 진짜 제목줄에 올린다** | **기각** | Qt 는 네이티브 제목줄에 위젯을 못 넣는다. 하려면 `FramelessWindowHint` + 드래그·스냅 레이아웃(WM_NCHITTEST)·더블클릭 최대화·시스템 메뉴를 전부 재구현해야 한다. 담당자 Windows PC 에 설치되는 앱에서 창 조작이 어긋나는 것은 **여백 30px 보다 훨씬 큰 손실**이고, 어설픈 커스텀 제목줄이야말로 P25 "싸구려 UI" 다 |
| **B. 워드마크(로고 + "Video Studio")** | **기각 — 캡처로 확인** | Windows 제목줄이 30px 위에서 **같은 아이콘·같은 글자**를 이미 그린다. 넣어 보니 같은 로고가 두 번 쌓여 렌더 버그처럼 보였다 (P12 중복). 정체성은 제목줄이 이미 말한다 |
| **C. 전폭 헤더바(제목·행동)** | 기각 | 화면마다 이미 제목 + 주요 버튼 행이 있다 — 제목이 두 줄이 된다 (P12·P23) |
| **D. 브레드크럼** | 기각 | 영상 화면이 이미 [← 프로젝트] + "프로젝트명 — N편 제목"을 머리에 단다 |
| **E. 검색창** | 보류 → 후보 | 지금 프로젝트가 3~4개다. 데이터가 적을 때 검색은 빈 컨트롤로 보인다 (P17). 수십 개가 되면 이 자리가 제자리 |
| **F. [새 영상 만들기]를 버튼으로 승격** | **채택** | 아래 |

- **결정**: 그 자리는 **기능**이 갖는다 — 좌측 열 머리의 **[+ 새 영상 만들기] 기본 버튼**.
  - 지적 10 이 내비 **목록의 한 행**으로 넣었는데, 목록의 나머지는 전부 "화면"인데
    이것만 "행동"이라 ⓐ 화면 이동으로 오해되고 ⓑ 하이라이트가 옮겨가면 안 되어
    `blockSignals`·`QTimer` 특례를 달고 있었다 (P11·P15). 버튼이 되면 둘 다 사라진다 —
    목록에는 화면만 남고(대시보드·라이브러리·작업 큐·설정), 시선이 가장 먼저 닿는
    좌상단에 Primary Action 이 앉는다 (P22).
  - **제목줄과의 차이**(사용자 조건): 흰 제목줄 위에 **채운 강조색 알약** — 색·형태가
    모두 다르고, 앞 회차의 1px 경계선이 두 영역을 가른다. 로고·글자 중복 없음.
  - 짝: 대시보드 [+ 새 프로젝트]는 **같은 대화상자**를 연다 — 둘 다 강조색이면 파란
    버튼 둘이 경쟁하므로(P15) 상시 노출되는 좌측 열이 Primary 를 갖고 대시보드 것은
    보조 버튼으로 내렸다.
  - 실측: 내비 4항목이 각자 제 화면에 도착 · 버튼 1클릭 = 위저드 1회 · 파고든 뒤
    '대시보드' 재클릭 복귀 정상 · pytest 147건
