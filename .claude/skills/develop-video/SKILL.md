# 프로젝트 영상 제작

프로젝트의 **실제로 동작하는 화면**을 찍어 영상으로 만든다. 목적(강의·홍보·매뉴얼·데모·쇼츠)에
따라 대본 구성과 연출만 달라지고, 파이프라인은 같다.

핵심 원칙은 **실화면이 가장 강한 증거**라는 것이다. AI로 만든 콘셉트 컷보다 제품이 실제로 돌아가는
화면이 설득력이 높다. 모션그래픽은 대체재가 아니라 도입·전환·강조에 쓰는 양념이다.

**찍을 화면이 없는 영상**(생애사·행사·일러스트 홍보)도 같은 파이프라인으로 만든다 — `scenes`를
비우면 녹화를 건너뛰고, 타이포 카드(`intro`·`chapter`·`stat`·`outro`) + 사진(`photo.html`, 켄번즈 줌)
+ 스톡 B롤(클립에 `file` 대신 `video`)을 이어 붙인다. 문법은 `references/authoring.md`의
"사진 구간"·"스톡 영상(B롤) 구간" 참조.

## 파이프라인

```
scenes.json → ① TTS 음성 → ② Playwright 화면 녹화 → ③ ffmpeg 합성 → out/<영상 id>/final/*.mp4 + *.srt
```

**오디오가 기준이다.** 음성을 먼저 만들어 길이를 재고 화면을 거기에 맞춘다.
**통짜로 찍고 나중에 자른다.** 씬 경계만 기록해 두면 길이가 다른 버전을 재촬영 없이 뽑는다.

## 끝까지 간다 — 중간에 멈추지 않는다

**1단계의 질문 한 라운드가 끝나면, 완성본이 나올 때까지 사용자에게 묻지 않는다.**
착수한 뒤로는 판단도 수정도 전부 스스로 한다. 이 스킬에서 사용자에게 말을 거는 지점은
**1단계(요구사항 4문항)와 8단계(완성 보고)뿐**이다.

**하지 말아야 할 것.**

| 금지 | 대신 |
|---|---|
| "이대로 진행할까요?" · "빌드를 돌려볼까요?" | 그냥 돌린다. 돌리는 게 이 스킬의 일이다 |
| "A안과 B안 중 어느 쪽이 좋을까요?" | 근거가 나은 쪽을 고르고, 8단계에서 왜 골랐는지 한 줄로 보고한다 |
| "화면이 비어 있는데 어떻게 할까요?" | 대체 화면을 찾아 바꾼다. 바꿨다는 사실을 기록에 남긴다 |
| 중간 산출물을 보여주며 "확인해 주세요" | 완성본까지 만든 뒤 한 번에 보여준다 |
| 빌드가 도는 동안 진행률만 반복 보고 | 그 시간에 **다음 단계를 미리 검증**한다(아래) |

**굽기 전에 잡을 수 있는 것은 굽기 전에 잡는다.** 이 파이프라인의 결함은 대부분 **오류를 내지
않는다** — 없는 params 는 조용히 지워지고, 잘못 둔 `wipe` 는 무시되고, 소스보다 긴 B롤은 마지막
프레임에서 얼어붙는다. 전부 "합성 성공"을 찍은 뒤 프레임을 뽑아야 드러나는데 한 번 굽는 데
수십 분이 든다. **그런데 판단 자료(대본 JSON·템플릿 html·B롤 파일)는 굽기 전에 이미 다 있다.**

그래서 `build.js` 는 **0단계 사전 점검**을 먼저 돌린다(자동. `--skip-preflight` 로만 끈다).
1초 안에 아래를 잡고, 치명적이면 **굽기 전에 멈춘다**.

| 잡는 것 | 안 잡으면 |
|---|---|
| 템플릿이 받지 않는 `params` 이름 | 그 글자가 화면에서 조용히 빠진 채 완성된다 |
| `wipe` 를 `params` 밖에 둔 것 | 흰 면이 그대로 떨어져 카드가 지워진 프레임이 남는다 |
| B롤 구간 > 소스 길이 | 넘어선 만큼 마지막 프레임이 정지 화면이 된다 |
| 템플릿·B롤 파일 없음, 화면 없는 구간 | 그 구간이 검은 화면으로 나온다 |

**점검이 뭐라고 하면 고치고 다시 돌린다. 끄고 굽지 않는다.** 여기서 1초에 잡을 것을 놓치면
30분을 굽고, 프레임을 뽑고, 고치고, 또 30분을 굽게 된다 — 실제로 그렇게 세 번 구웠다.

**빌드가 도는 동안이 검증 시간이다.** 촬영·합성은 수십 분 걸리고 그동안 손이 비는데, 여기서
멈춰 서서 기다리기만 하면 완성된 뒤에야 결함을 발견하고 처음부터 다시 돌리게 된다. 기다리는
동안 **씬으로 쓸 스크린샷을 전부 열어 내레이션과 대조하고**, 렌더된 모션 클립에서 프레임을 뽑아
글자가 제대로 나오는지 본다. 실제로 이 순서를 지켰더니 빈 화면 1건·문구 불일치 5건·글꼴 깨짐
1건이 나왔다 — 전부 완성 후에야 드러났을 것들이다.

**고칠 것이 나오면 고치고 다시 돌린다.** "이미 빌드가 돌고 있으니 다음에" 하지 않는다.
재촬영이 아까우면 `--only compose`로 끝나는 것인지 먼저 따져 보고, 재촬영이 필요하면 재촬영한다.
**결함을 알면서 넘긴 산출물을 완성본이라고 보고하지 않는다.**

**"완료"라고 말할 수 있는 조건.** 아래를 전부 충족해야 8단계 보고를 한다.

- `final/`에 mp4와 srt가 있고 `ffprobe`로 길이·해상도·코덱을 실제로 쟀다
- **프레임을 뽑아 눈으로 봤다** — 밝은 화면 1장·어두운 화면 1장(워터마크 가독성), 모션 카드 1장 이상
- 자막에 수정한 문구가 실제로 반영됐는지 `.srt`에서 확인했다
- 남은 판단 사항(도메인·색상 확정 등)을 목록으로 정리했다

**고쳤으면 재채점까지가 한 묶음이다.** 9단계 평가에서 지적을 받아 무언가를 고쳤다면,
**고친 뒤 평가 agent를 다시 띄워 점수를 다시 받는다.** "재채점은 아직 안 돌렸습니다,
돌릴까요?"라고 묻지 않는다 — 고친 것이 실제로 점수를 올렸는지는 다시 받아 봐야 알고,
그 확인까지가 작업이다. 점수가 안 올랐으면 그 사실도 그대로 보고한다.

**단, 재채점은 한 번이다. 점수를 올리려고 반복하지 않는다.**

| 무엇이 완료를 정하는가 | |
|---|---|
| **결함이 사라졌는가** | 이것이 기준이다. 잘린 문장·흰 프레임 같은 **객관적 결함**은 고친다 |
| 점수 몇 점인가 | **기준이 아니다.** 목표 점수를 정해 놓고 거기 닿을 때까지 돌리지 않는다 |

고친 것이 **하나뿐이고 확인이 기계적이면 재채점 대신 직접 확인한다** — `.srt`를 grep 하거나
프레임을 뽑아 보면 끝나는 일에 agent를 다시 띄우는 것은 낭비다. 재채점은 **여러 곳을 고쳐
전체 인상이 달라졌을 때** 의미가 있다.

점수는 **보고용 지표이지 목표가 아니다.** 3점대가 나와도 지적된 결함이 전부 해소됐고 남은
감점 사유가 판단의 문제(길이·톤·취향)라면 거기서 멈추고, **무엇이 왜 남았는지 사용자에게
그대로 전한다.** 더 고칠지는 사용자가 정한다. reviewer 의 점수 정의상 **4점이 "내보내도 된다"**의
경계이니, 4 미만이면 그 이유를 반드시 함께 보고한다.

막혀서 정말 사용자 결정이 필요하면, **막힌 부분만 남기고 나머지는 전부 완성한 뒤**
"이것만 정해 주시면 됩니다"로 묻는다. 아무것도 안 만든 채로 묻지 않는다.

## 진행 순서

### 1. 요구사항 확정 — 첫 질문 한 라운드

영상은 되돌리기가 비싸다. 대본을 쓰고 촬영하고 합성한 뒤에 "남자 목소리로 해주세요"를 들으면
음성·타이밍·자막이 전부 다시 간다. 그래서 **만들기 전에 한 번만 묻는다.**

**AskUserQuestion 한 번에 최대 4개를 묶어 묻는다. 라운드는 한 번이다.** 나눠서 여러 번 물으면
사용자는 심문당한다고 느낀다. 아래 원칙을 지킨다.

- **요청에 이미 있는 항목은 빼고 묻는다.** "남자 목소리로 강의 영상 만들어줘"면 목소리·용도는 이미
  정해졌다 — 남은 두 개만 묻는다. 4개를 채우려고 아는 것을 다시 묻지 않는다.
- **선택지는 지금 실제로 되는 것만 올린다.** 묻기 전에 `node tools/video/check-tts.js`를 돌려
  **살아 있는 제공자만** 목소리 선택지에 넣는다. azure 키가 죽어 있으면 azure를 올리지 않는다.
- **기본값에 `(권장)`을 붙여 첫 번째에 둔다.** 사용자가 그냥 엔터를 쳐도 맞는 답이 나와야 한다.
- **바꾸기 싼 것은 묻지 않는다.** 자막 글꼴·색·crf 따위는 나중에 `--only compose`로 몇 초면 바뀐다.

#### 묻는 4가지

| # | 질문 (header) | 선택지 | 이게 바꾸는 것 |
|---|---|---|---|
| 1 | 영상 종류 (`용도`) | 강의·학습 **/** 홍보 **/** 사용 매뉴얼 **/** 쇼츠 | 대본 골격·길이·변형·BGM 기본값 |
| 2 | 화면 소재 (`소재`) | 앱 화면 녹화 **/** 타이포 모션만 **/** 사진+B롤 **/** 앱+모션 혼합 | 파이프라인 분기(녹화 유무) |
| 3 | 목소리 (`목소리`) | **선희·edge (권장)** **/** 남성(인준)·edge **/** azure(뉴럴) **/** eleven(유료·최고품질) — azure·eleven 은 check-tts 에서 살아 있을 때만 올린다 | `voice.gender`·`voice.provider` |
| 4 | 배경음악 (`BGM`) | 없음 **/** 낮게 깔기 **/** 후보 들어보고 고르기 | `render.bgm`·`bgmGain` |

**선택 → 설정 매핑.** 답을 받으면 그대로 아래로 떨어뜨린다.

| 답 | 반영 |
|---|---|
| 강의·학습 | `scenes.manual.json` 골격 + 단계마다 `chapter.html`, `hold` 길게, 16:9만, BGM 0.08 이하 |
| 홍보 | `scenes.promo.json` 골격 + 30초, 첫 5초에 결과, 16:9 `captions:false` + 쇼츠 포함 |
| 사용 매뉴얼 | `scenes.manual.json` 골격 + 클릭 전 `highlight`, 인물 PiP·BGM 끔 |
| 쇼츠 | 9:16 변형만(`--only-shorts`), 45초 이하, `subtitleMargin` 0.185·`watermarkMargin` 0.075 |
| 앱 화면 녹화 | `scenes[]`에 `actions` 작성 — 셀렉터를 저장소에서 **실제로 확인**(2단계) |
| 타이포 모션만 | `scenes: []` + `render.motion.clips`만. 앱을 띄울 필요 없다 |
| 사진 + B롤 | `photo.html`(켄번즈) + 클립에 `video`. **`assets/`에 이미 받아둔 것**을 쓰거나 링크를 받는다 |
| 선희(기본)/남성 | `--gender female|male`. 여성 = `ko-KR-SunHiNeural`(선희) · 남성 = `ko-KR-InJoonNeural`(인준) |
| edge / azure / eleven | `--provider edge|azure|eleven`. azure·eleven이 죽으면 자동으로 edge로 내려간다 |
| BGM 고르기 | `assets/bgm`의 후보를 `ffplay`로 들려주고 **사람이 고른다**. 자동 선택 금지 |

#### 묻지 않는 것

| 항목 | 왜 |
|---|---|
| 자막 | 기본으로 항상 굽는다. 요청이 있을 때만 `subtitles:false`(`.srt`는 그대로 나감) |
| 워터마크 | 항상 넣는다. `render.watermark.text`만 채우면 된다 |
| 언어 | 기본 ko. 요청이 외국어면 그때 `--lang` |
| 길이·해상도·글꼴 | 기본값으로 진행하고, 필요하면 `--only compose`로 나중에 바꾼다 |

#### 지금 못 하는 것 — 선택지에 올리지 않는다

| 요구 | 현실 | 대신 |
|---|---|---|
| Pexels·Pixabay 자동 검색 | 검색 API는 키가 필요해 붙이지 않았다 | 사람이 링크를 고르고 `assets/fetch.js`로 받는다 |
| 웹 이미지 검색해 쓰기 | 저작권·초상권 문제. "지켜야 할 선" 위반 | 무료 스톡(Mixkit·Pexels·Pixabay·Coverr)만 |

요청에 없고 질문으로도 안 나온 나머지는 이 기본값으로 간다.

| 항목 | 기본값 |
|---|---|
| 언어 | ko |
| 쇼츠(세로) | 홍보=포함, 매뉴얼·강의=제외 |
| 길이 | 홍보 30초 · 쇼츠 45초 이하 · 매뉴얼·강의 제한 없음 |

### 2. 프로젝트 파악

**추측하지 말고 저장소를 읽는다.**

- 제품 이름·한 줄 설명·실제 기능: `README.md`, 랜딩 페이지 문구, 설계 문서
- 개발 서버 실행법과 포트: `package.json` scripts, `docker-compose*.yml`, README
- 화면 경로: 라우터 파일 (`router/*`, `App.tsx`, `pages/`, `routes/`)
- 조작할 셀렉터: 해당 화면 컴포넌트에서 `id`, `data-testid`, 버튼 텍스트를 **실제로 확인**
- 브랜드 색·글꼴: 디자인 토큰 파일 (`tokens.css`, `tailwind.config.*`, `theme.*`)

내레이션에 **없는 기능이나 검증되지 않은 수치를 쓰지 않는다.** 저장소에 근거가 있는 문구만 쓴다.

### 3. 스캐폴딩

스킬의 `scripts/`와 `templates/motion/`을 프로젝트로 복사한다 (기본 위치 `tools/video/`).

```bash
mkdir -p tools/video
cp -r <skill>/scripts/build.js <skill>/scripts/check-tts.js <skill>/scripts/lib tools/video/
cp -r <skill>/templates/motion tools/video/
cp <skill>/templates/package.json tools/video/          # "type": "module" — 없으면 구형 Node에서 import가 안 돈다
cp <skill>/templates/.env.sample tools/video/          # 키를 쓸 때만 .env 로 복사해 채운다
npm --prefix tools/video i -D playwright && npx playwright install chromium   # 저장소에 이미 있으면 생략
```

**키를 어디에 두나.** `.env`는 `tools/video/.env` → 상위 → 저장소 루트 순으로 찾고, 저장소
표시(`.git`·`package.json`)를 만나면 거기서 멈춘다. **기본 경로(edge)는 키가 아예 필요 없으니
대개 아무것도 안 만들어도 된다.**

**우선순위는 셸 환경변수 > 프로젝트 `.env` > 이 PC 공용 파일** 순이고, 먼저 잡힌 값이 이긴다.

| 상황 | 둘 곳 |
|---|---|
| 기본 (edge) | 없음 — 키가 필요 없다 |
| **여러 프로젝트에서 공용 (권장)** | **`~/.claude/develop-video.env`** (Windows `%USERPROFILE%\.claude\develop-video.env`). 한 번 채우면 이 PC 의 모든 프로젝트가 본다 — **스킬 폴더만 복사해 온 새 프로젝트에서도 그대로 잡힌다** |
| 이 프로젝트만 다른 키 | `tools/video/.env` (`.env.sample`을 복사해 채운다). 공용 파일보다 우선한다 |
| CI·일회성 | 셸 환경변수. 무엇보다 우선한다 |

**스킬 폴더 안에는 `.env`를 두지 않는다.** 두어도 읽히지 않고(탐색 경로에 없다), 무엇보다
**스킬 폴더는 프로젝트 사이를 복사해 다니라고 만든 물건**이라 키를 넣으면 사본마다 비밀이
따라간다 — 남에게 스킬을 건네는 순간 같이 건너간다. 교체할 때도 사본을 전부 찾아다녀야 한다.
키는 위 세 곳 중 하나에 두고 코드가 찾아가게 한다. 저장소에는 `.env.sample`만 커밋한다.

**대본을 쓰기 전에 파이프라인부터 한 번 돌린다.** 앱도 대본도 없이 20초 만에 끝나고,
ffmpeg·Playwright·TTS·자막·워터마크가 전부 도는지 확인된다. 여기서 막히면 대본을 아무리 잘 써도 소용없다.

```bash
cp <skill>/templates/scenes.selftest.json tools/video/
node tools/video/check-tts.js                                        # 소리부터
node tools/video/build.js --scenes tools/video/scenes.selftest.json  # out/selftest/final/ 에 2개
```

#### 다른 프로젝트로 옮기기 — 스킬 폴더가 전부다

**이 스킬은 프로젝트에 묶여 있지 않다.** 스크립트는 저장소 이름·경로를 하나도 모르고, 필요한 것은
ffmpeg · Playwright · edge-tts뿐이다 (단, 기본값이 한국어다 — 다른 언어는 `--lang`, 자막 글꼴은
`render.subtitleFont`로 바꾼다).

**스킬 폴더 밖에는 아무것도 두지 않는다.** 예전에는 컨셉 검증 워크플로가 `.claude/workflows/`에,
제작 기록 형식이 `.claude/memory/README.md`에 있어서 폴더만 복사하면 4단계·8단계가 조용히
깨졌다. 지금은 전부 안에 있다.

| 기능 | 어디에 | 부르는 법 |
|---|---|---|
| 컨셉 검증(4단계) | `workflows/video-concept.js` | `Workflow({scriptPath: ...})` — 경로를 직접 준다 |
| 제작 기록 형식(8단계) | `templates/memory-record.md` | 읽어서 `.claude/memory/<id>.md`를 쓴다 |
| 평가 지침(9단계) | `agents/reviewer.md` | `general-purpose` 에게 이 파일을 읽게 한다 |

그래서 옮기는 일은 **폴더 복사 + 스캐폴딩** 두 가지뿐이다.

```bash
cp -r <이 저장소>/.claude/skills/develop-video  <대상>/.claude/skills/
cp -r <이 저장소>/.claude/skills/develop-lecture <대상>/.claude/skills/   # 강좌를 만들 때만
# 그다음 대상 저장소에서 위 스캐폴딩 명령을 그대로 실행한다
```

**단 하나 따라가지 않는 것이 `assets/`다** — 무료 스톡은 재배포가 금지라 git 에서 제외한다.
`assets/CATALOG.md`(출처·라이선스)와 `assets/fetch.js`(받아오기)는 따라가므로, 대상에서 필요한
소재만 다시 받는다. 대본이 없는 소재를 가리키면 0단계 사전 점검이 굽기 전에 잡아 준다.

`.gitignore`에 산출물을 추가한다.

```
/tools/video/out/*
!/tools/video/out/*/
!/tools/video/out/*/final/
/tools/video/out/*/*
*.mp4
*.webm
/tools/video/presenter/

.env
!.env.sample
```

### 4. 컨셉 검증 — 대본 전에 도입부를 확정한다

**도입부가 성패를 가르는 영상은 대본을 쓰기 전에 컨셉을 검증한다.** 훅을 잘못 잡으면 대본·촬영·
합성이 전부 헛일이 되고, 그 사실은 완성한 뒤에야 드러난다. 되돌리기가 비싼 것은 목소리만이 아니다.

스킬 안의 `workflows/video-concept.js`를 Workflow 도구로 돌린다. `scriptPath`는 아무 경로나
받으므로 `.claude/workflows/`에 따로 두지 않는다 — 스킬 폴더 하나만 복사하면 그대로 따라온다.

```
Workflow({
  scriptPath: ".claude/skills/develop-video/workflows/video-concept.js",
  args: {
    brief: "<무엇에 대한 영상인가 — 한 문장>",
    videoId: "<out/<영상 id>/ 와 같은 id>",
    kind: "<쇼츠|홍보|강의>",
    constraints: "<9:16, 60초 이내, 앱 화면 없음 같은 제약>"
  }
})
```

컨셉 5안을 **서로 모르는 상태로 병렬 생성**한 뒤, 안마다 세 관점이 동시에 심사한다.

| 관점 | 무엇을 죽이는가 |
|---|---|
| 제작가능성 | `assets/`·`motion/`을 실제로 열어 본다. **소재가 없어 착수 불가한 안**을 걸러낸다 |
| 후킹 | 3초 안에 스크롤이 멈추는가. 훅이 가정하는 시청자 심리가 실재하는가 |
| 사실검증 | 등장하는 **모든 수치의 출처를 저장소에서 찾는다.** 못 찾으면 위험 표시 |

한 관점이라도 `blocker`를 매기면 그 안은 탈락한다. 생존안 중 하나를 골라 지적을 반영해 수정한 뒤
최종안·미해결 리스크·차점안을 돌려준다.

**돌릴 때와 건너뛸 때.**

| 돌린다 | 건너뛴다 |
|---|---|
| 쇼츠 — 3초 훅이 전부다 | 사용 매뉴얼 — 순서가 곧 구조다 |
| 홍보 — 첫 5초에 결과가 나와야 한다 | 릴리스 노트 — 내용이 이미 정해져 있다 |
| 강의 — 도입부에서 이탈이 갈린다 | 사용자가 컨셉을 이미 지정했다 |

건너뛰는 경우라도 사용자가 검증을 요청하면 돌린다.

**싼 작업이 아니다.** 에이전트 13개가 5~10분 돌고 **50만 토큰 안팎**을 쓴다(실측: 3안 × 3관점
+ 종합). 짧은 데모나 컨셉이 이미 정해진 영상에 습관적으로 걸지 않는다. 이 비용을 정당화하는 것은
검증이 잡아내는 것이 **완성 후에야 드러나는 종류의 실패**라는 점이다 — 실제로 첫 실행에서
사진 구도가 컨셉의 전제와 다르다는 것(매치컷 불가), `build.js`의 클립 길이 하한 때문에 3초 훅이
10초로 부푼다는 것, 화면 정중앙에 띄울 수치의 출처가 저장소에 없다는 것을 잡아냈다.

**`brief` 를 반드시 채운다.** 비어 있으면 워크플로가 에이전트를 하나도 띄우지 않고 즉시 중단한다.
`args` 는 JSON 문자열이 아니라 **객체로** 넘긴다 — 문자열로 넘기면 전달되지 않는다.

**결과는 사용자에게 보인다.** 사용자가 실시간으로 응답하는 세션이면 승인을 받고, 아니면
(자율 실행) 확정안대로 진행하되 **왜 그 안을 골랐는지와 openRisks 를 8단계 보고에 그대로
싣는다** — "끝까지 간다" 원칙이 이 절보다 우선한다. 특히 `openRisks`에 남은 미검증 수치를 그대로
전한다 — 검증 전까지 그 숫자를 내레이션에 넣지 않는다(2단계 "저장소에 근거가 있는 문구만 쓴다").

돌린 뒤에는 결과를 `.claude/debate-logs/<영상 id>-concept.md`에 남긴다. 왜 그 컨셉이 됐고
어떤 안이 왜 죽었는지가 8단계 제작 기록의 근거가 된다.

### 5. 대본 작성

**영상 한 편의 입력물은 `tools/video/projects/<영상 id>/` 한 폴더에 모은다** — 대본은
`projects/<영상 id>/scenes.json`, 그 영상에서만 쓰는 전용 모션 템플릿·조사 자료(facts)·데모
서버도 같은 폴더에 둔다. 대본을 `tools/video` 직속에 `scenes.<이름>.json`으로 평평하게 두면
영상 수만큼 무한히 쌓인다 — 실제로 열 개가 쌓인 뒤에 이 구조로 바꿨다.

- 폴더 이름 = 영상 id = `out/<영상 id>/`. 셋을 맞추면 `--project <id>` 하나로 대본을 찾는다.
- 전용 모션 템플릿은 공용 `_base.css`·`_params.js`를 `../../motion/` 상대 경로로 참조한다.
  합성은 대본 폴더를 먼저 뒤지고 없으면 공용 `motion/`으로 내려간다.
- 실험용 대본·중간 산출물 같은 임시 파일은 저장소에 만들지 않는다 — 렌더 중간물은
  `out/<id>/work/`가 그 자리다(언제든 지워도 된다). 저장소 안에 임시 파일을 만들 수밖에
  없었다면 작업이 끝날 때 지운다.
- 점검용 `scenes.selftest.json`만 예외로 직속에 남는다.

#### 대본을 쓰기 전에 — 구성표부터 만든다 (5분이면 된다)

**문장부터 쓰기 시작하면 반드시 되돌아온다.** 실제로 그랬다 — 대본을 다 쓰고 음성까지 뽑은
뒤에야 "기술 설명 구간이 전부 글자 카드"라는 것과 "분량이 목표의 3분의 2"라는 것을 알았고,
대본을 3차까지 다시 썼다. **아래 표를 먼저 채우면 그 두 가지가 착수 전에 결정된다.**

| 구간 | 무엇을 말하나 | **화면은 무엇인가** | 글자수 | 소재 길이 |
|---|---|---|---|---|
| ch1 | 오해 격파 | 챕터 카드 | 20 | — |
| b1 | 데이터센터 실물 | B롤 `ai-datacenter` | 90 | **13.3s** |
| s1 | 빌린다는 정의 | **도식** `cloud-rent` | 210 | — |

이 표가 강제하는 것이 셋이다.

**① 화면 칸을 먼저 채우면 "글자 카드로 때운 구간"이 눈에 보인다.** 기술 설명 구간에 `stat` 이
연달아 있으면 그 자리가 비어 있다는 뜻이다 — 도식을 그려야 한다(위 "개념 구간에는 도식" 참조).
**대본을 다 쓴 뒤에 세면 이미 늦다.**

**② 글자수를 먼저 배분하면 분량이 맞는다.** 목표 길이 × 초당 글자수 = 총 글자수이고, 그걸
구간에 나눠 준 뒤 그 예산 안에서 문장을 쓴다. **표준은 초당 6.3자(5분 ≈ 1,800자)다** —
이 페이스가 나오는 rate 를 목소리에 맞춰 준다: 선희 `+6%` · 인준 `+15%`(같은 문단 A/B 실측으로
맞춘 값 — 인준을 `+6%`로 두면 초당 5.9자라 5분 기준 30~40초 모자란다. 실제로 그랬다).
다른 목소리·언어를 쓰면 `--only tts` 로 한 구간만 뽑아 `음성 길이 ÷ 글자수` 로 rate 를 6.3에
맞춘다. 어림으로 "초당 5자"를 잡았다가 4분 27초가 나온 적이 있다.

**③ 소재 길이를 먼저 재면 B롤이 얼어붙지 않는다.** B롤 구간의 내레이션은
**(소스 길이 − `videoStart`) × 6.3자** 안에 들어와야 한다. 넘으면 남는 시간이 정지 화면이 된다.

```bash
for f in <소재>/*.mp4; do printf "%-20s " "$(basename $f)"; \
  ffprobe -v error -show_entries format=duration -of csv=p=0 "$f"; done
```

구성표는 머릿속에 두지 말고 **`projects/<영상 id>/plan.md` 로 남긴다** —
`templates/plan.md` 를 복사해 채우면 된다(확인 항목까지 딸려 온다). 8단계 제작 기록에서
"왜 이 구간을 이렇게 만들었나"의 근거가 되고, 다음 영상에서 배분을 재사용할 수 있다.

#### 그다음에 대본을 쓴다

용도에 맞는 템플릿을 `projects/<영상 id>/scenes.json`으로 복사하고 **대괄호 부분을 전부 실제
값으로 채운다**.

- 홍보: `templates/scenes.promo.json`
- 매뉴얼: `templates/scenes.manual.json`

**템플릿은 골격만 준다. 실제로 돌려서 나온 값은 `examples/`에 있다** — 대본을 쓰기 전에 읽는다.

- [`examples/ttalkak-slide-promo.md`](examples/ttalkak-slide-promo.md) — 한 번 촬영해 변형 5종을 뽑은
  홍보영상 기록. 씬별 실측 길이("15초 버전"이 왜 19.9초인지), 약한 씬을 모션으로 갈아 끼우는 법,
  프레임 두 장(16:9에서 헤드라인이 앱을 가린 사례 · 9:16에서 같은 문구가 안 가리는 이유),
  조정값과 `optional` 판단 기준. 대본 원본은 `examples/ttalkak-slide-promo.scenes.json`.
- **강의 예제는 저장소의 실전 대본이 맡는다** — `tools/video/projects/cloud-lecture/`(B롤+도식
  혼합, 선희)와 `tools/video/projects/rest-api-lecture/`(전용 도식만, 인준, 훅-회수 구조).
  제작 판단의 근거는 `.claude/memory/<영상 id>.md` 에 있다.

**혼자서는 정할 수 없는 수치**(`zoom`·`focusX`·`focusY`·`padY`·`crop`·`subtitleMargin`·`rate`)는
예제 값에서 출발한다. 기본값은 대개 틀리고, 예제 값은 최소한 한 번은 눈으로 확인된 값이다.

**화면에 항상 있는 것 두 가지** — 기본값이 그렇고, 자막만 명시적으로 끌 수 있다.

- **자막**: 말이 있는 모든 구간(씬·모션)에 **기본으로 항상 굽는다.** 길어서 한 화면에
  안 들어가면 잘리지 않고 여러 장으로 나뉜다. `.srt` 사이드카도 같은 내용으로 함께 나간다.
  **사용자가 "자막이 지저분하다"고 요청할 때만 `render.subtitles: false`로 끈다** — 이때도
  **`.srt`는 그대로 나간다.** 화면에 굽는 것만 빠지므로 유튜브에 올릴 때 자막 파일을 첨부하면
  시청자가 필요할 때 켤 수 있다. 소리를 켜지 않고 보는 시청자가 다수라 **먼저 제안하지는 않는다.**
- **워터마크**: 첫 프레임부터 끝 프레임까지, 기본 **오른쪽 위**. 반투명 판 없이 글자만 얹는다.
  `render.watermark.text`를 **반드시 채운다**(비면 합성 때 경고가 뜨고 표기가 빠진다).
  세로 변형은 `watermarkMargin: 0.075`로 내려 유튜브 상단 UI를 피한다.

#### 개념을 설명하는 구간에는 도식을 그린다 — 글자 카드로 때우지 않는다

**말로 설명하는 것과 화면이 설명하는 것은 다른 일이다.** 내레이션이 "몰릴 때만 늘렸다 줄인다"라고
말하는 동안 화면에 "몇 분이면"이라는 큰 글자만 떠 있으면, 그 구간의 화면은 **아무것도 설명하지
않은 것**이다. 시청자는 소리를 끄면 아무것도 못 얻는다.

**대본을 쓰면서 구간마다 이렇게 자문한다 — "이 화면을 소리 없이 보면 뭘 알 수 있나?"**

| 구간이 말하는 것 | 화면에 있어야 할 것 |
|---|---|
| 구조·계층 (3층 구조, 무엇을 누가 맡나) | 층이 쌓인 그림 + **색으로 갈린 담당 범위** |
| 변화·흐름 (요청이 몰린다, 서버가 늘어난다) | 시간에 따라 **실제로 늘어나고 줄어드는** 그림 |
| 비교 (예전 방식 vs 클라우드) | 좌우로 놓고 **다른 점이 눈에 띄는** 그림 |
| 위치·관계 (어디에 있나, 무엇과 연결되나) | 지도·연결선 |
| 숫자 하나를 각인 (3배·1분·99%) | **stat 카드** — 이때가 stat 카드의 자리다 |

**`templates/motion/`에 새 html을 만드는 것을 주저하지 마라.** 스톡에 없는 그림은 직접 그린다 —
`riversection.html`이 그 예다(한강 단면도. 저수로·둔치·제방의 높이 관계를 보여 주려고 새로 그렸다).
CSS 애니메이션 + SVG면 충분하고, `_base.css`·`_params.js`를 불러 쓰면 params·색·와이프가 그대로 붙는다.

**도식의 등장 시각은 내레이션이 그 말을 하는 시각에 맞춘다 — 그리는 것의 절반이 타이밍이다.**
템플릿 습관대로 0.5~3초 스태거로 두면 40초 내레이션 구간에서 그림이 3초 만에 완성되고 나머지
37초가 정지 화면이 된다. 요소별 `animation-delay`를 대본의 발화 시각(초당 6.3자로 역산)에
놓아라 — "겟은 조회"가 4.5초에 나오면 GET 행도 4.5초에 뜬다. 같은 템플릿을 말 속도가 다른
두 구간에 쓰면 지연을 `t1`·`t2`… params 로 빼서 구간마다 넘긴다(rest-api-lecture 의
`rest-line.html` 이 그 예다). 빌드 전에 프로토 렌더로 중간 시각 프레임을 뽑아 "말이 아직 안 한
것이 미리 다 떠 있지 않은지"를 본다.

**스톡 B롤은 분위기 담당이다.** 도입·전환·감정에 쓴다. 데이터센터 영상이 "클라우드는 실재하는
건물"이라는 인상은 주지만 오토스케일링을 설명하지는 못한다. **기술 설명 구간을 B롤로 채우면
그 구간은 비어 있는 것이다.**

용도별 연출 차이는 이렇다.

**홍보** — 첫 5초에 결과물이 보여야 한다(스킵 버튼이 뜨는 시점). 씬은 짧게, 수치는 뱃지로 강조.
16:9는 `captions: false`(상단 헤드라인만 끈다 — 자막과 중복되고 앱 헤더를 가린다), 세로는 caption 유지.

**매뉴얼** — 단계마다 `chapter.html` 카드를 넣어 "지금 몇 번째"를 계속 알린다. `hold`를 길게 잡아
따라 할 시간을 준다. 클릭 전에 `highlight`로 어디를 누르는지 먼저 보여준다. 인물 PiP·BGM은 끈다.

셀렉터가 확실하지 않은 액션에는 **반드시 `"optional": true`를 붙인다.** 없으면 셀렉터 하나가
30초를 먹고 영상을 망친다.

자세한 문법과 함정은 `references/authoring.md`를 읽는다.

### 7. 검증 — 눈으로 확인한다

**만들고 끝내지 않는다.** 프레임을 뽑아 실제로 본다. 뽑은 프레임은 그 영상의 `frames/`에 둔다 —
"봤다"는 말보다 남은 파일이 낫고, 다음에 고칠 때 이전 상태와 견줄 수 있다.

```bash
cd tools/video/out/<영상 id>
ffmpeg -v error -y -ss <초> -i final/<변형>.mp4 -frames:v 1 -vf scale=960:-1 frames/<변형>-t<초>.png
```

확인할 것: 셀렉터가 맞아 의도한 화면이 찍혔는가 · 문구가 UI를 가리지 않는가 · 세로 변형에서
자막이 유튜브 UI 영역(하단 330px·우측 160px)을 벗어났는가 · 로딩 스켈레톤이 찍히지 않았는가.

**밝은 화면 한 장·어두운 화면 한 장을 반드시 뽑아 오른쪽 위를 본다.** 워터마크가 두 배경 모두에서
읽히고, 회색 판때기 없이 글자만 얹혀 있어야 한다. 말이 있는 구간이면 자막도 함께 보여야 한다.

**마지막 클립도 반드시 뽑는다.** 앞부분 몇 장만 보고 "깨끗하다"로 넘기면 끝에서 걸린다 —
실제로 outro 의 CTA 알약이 자막과 겹쳐 마지막 4초가 통째로 못 읽는 화면이었는데, 검증이
t=2·6·14 에서 끝나 만든 쪽은 몰랐고 평가 agent 가 찾았다.

**오디오도 잰다 — 프레임에는 절대 안 보인다.** 문장 사이 무음이 2초씩 벌어져 30초 쇼츠의
절반이 정적이어도 프레임 검증은 전부 통과한다.

```bash
ffmpeg -hide_banner -nostats -i final/<변형>.mp4 -af "silencedetect=n=-40dB:d=0.8" -f null -
```

잡힌 무음은 **원인부터 갈라야 한다** — 처방이 다르다.

| 무음의 모양 | 원인 | 처방 |
|---|---|---|
| 특정 클립 끝에 몰려 있고 길이가 제각각 | `duration`을 오디오보다 길게 고정해 둠 | `duration`을 빼서 하한(오디오+0.5초)에 맡긴다 |
| **문장 사이마다 1.2~1.4초로 균일** | TTS 의 문장 간 호흡 — 편집 결함이 아니다 | BGM 이 없으면 전부 그대로 노출된다. 늘어지면 BGM 0.08 로 메운다(아래) |

TTS 제공자가 mp3 앞뒤에 붙이는 무음은 합성 직후 자동으로 잘리므로(`lib/tts.js`) 클립
경계 무음은 위 둘 중 하나다. **BGM 없는 영상은 문장 호흡이 전부 무음으로 잡힌다는 것을
알고 읽어라** — BGM 0.08 을 깐 영상이 무음 0건으로 나오는 것은 리듬이 좋아서가 아니라
BGM 이 바닥을 채워서다(cloud-lecture 가 그랬다). 반대로 BGM 없는 4분 51초 강의에서
문장 호흡 71건·합 93초가 잡힌 사례가 있다 — 이건 결함이 아니라 선택의 결과이니
사용자에게 그대로 보고하고 유지/BGM 중에서 고르게 한다.

#### 소리를 끄고 본다 — 설명 영상의 진짜 합격선

위 항목은 전부 **"읽히는가"**만 본다. 그것만 보면 기술적으로 완벽하면서 아무것도 설명하지 못하는
영상이 그대로 통과한다. 그래서 한 가지를 더 본다.

**기술적 개념을 설명하는 구간에서 프레임을 뽑아, 소리를 끄고 그 화면만 보라.
그림이 개념을 설명하고 있는가, 아니면 내레이션을 글자로 옮겨 적어 둔 것뿐인가?**

| 통과 | 불합격 |
|---|---|
| 서버 한 대가 요청에 눌리다가 **여러 대로 늘어나는** 그림 | "확장성"이라고 쓴 큰 글자 |
| 3층 상자에 **내가 맡는 부분·빌리는 부분**이 색으로 갈린 그림 | "IaaS · PaaS · SaaS" 라는 글자 |
| 파일이 **여러 곳에 복제되는** 그림 | "여러 곳에 나눠 보관" 이라는 문장 |

**stat 카드는 요약이지 설명이 아니다.** 숫자 하나를 각인시킬 때(`3배`·`1분`) 쓰는 물건이고,
**구조·흐름·비교·시간에 따른 변화**를 말하는 구간에 stat 카드를 놓으면 그 구간은 설명이 비어 있는
것이다. 그런 구간은 **도식을 직접 그린다** — `templates/motion/`에 새 html을 하나 만들면 된다
(`riversection.html`이 그렇게 만든 예다. 스톡에 없는 그림이라 직접 그렸다).

**스톡 B롤은 분위기이지 설명이 아니다.** 데이터센터 영상은 "클라우드가 실재하는 건물"이라는
정서를 주지만, 오토스케일링이 무엇인지는 1초도 설명하지 못한다. 도입·전환·감정에 쓰고,
**기술 설명 구간은 도식으로 받는다.** 개념 강의에서 B롤만으로 채웠다면 그 영상은 다시 만들어야 한다.

**무엇을 보고 판단하는지는 `examples/`의 프레임 두 장이 그대로 보여 준다** — 같은 시각을 16:9와
9:16에서 뽑아 놓았고, 16:9 쪽은 실제로 헤드라인이 앱 UI를 덮은 상태다. 뽑은 프레임을 그것과 견준다.

싱크는 음성 시작 시각으로 확인한다(`references/authoring.md` 참조). 오차가 일정하면 정상,
점점 커지면 드리프트다.

### 8. 재생·보고·기록

`ffplay -autoexit -x 1280 -y 720 out/<영상 id>/final/<변형>.mp4`로 직접 재생해 보여 준다.
(Windows 기본 연결 앱은 실행되지 않는 경우가 있다.)

산출물 위치(`out/<영상 id>/final/`)와 **남은 판단 사항**(BGM 음원, 카피 확정, 도메인 등)을
함께 보고한다.

그리고 **제작 기록을 남긴다** — `.claude/memory/<영상 id>.md`. 형식은 스킬 안의
[`templates/memory-record.md`](templates/memory-record.md)에 있고(프로젝트 쪽에 사본을 두지
않는다 — 두면 갈라진다), id는 `out/<영상 id>/`와 반드시 같게 쓴다. `out/`은 용량 때문에 지워질
수 있지만 기록은 남는다.

채우는 것은 **`## 평가`를 뺀 전부** — 무엇을 왜 그렇게 만들었는지, 소재의 출처와 라이선스,
걸린 지점과 해결 방법, 남은 판단 사항. **걸린 것을 빠뜨리지 마라** — 다음 영상에서 같은 데
걸리지 않으려고 적는 것이고, 몰아 쓰면 제일 먼저 날아간다. `score:`는 `null`로 두고 자평하지 않는다.

### 9. 평가 — 별도 agent에게 맡긴다

영상이 완성된 **뒤에만** 한다. Agent 도구로 **`general-purpose`** 를 띄우고, 평가 지침
`agents/reviewer.md`를 읽게 한다.

```
subagent_type: general-purpose
prompt: |
  .claude/skills/develop-video/agents/reviewer.md 를 먼저 읽고 거기 적힌 절차·채점 기준을
  그대로 따라 영상 한 편을 평가하라.
  video_id=<영상 id>, video_root=tools/video
```

**`subagent_type: video-reviewer` 로 부르지 않는다.** Claude Code 의 agent 레지스트리는
`.claude/agents/*.md` 만 읽고 스킬 하위 `agents/` 는 스캔하지 않는다 — 그 이름으로 부르면
"없는 agent" 로 실패한다. 지침을 파일로 넘기면 **스킬 폴더만 복사해도 평가가 그대로 돈다.**
`.claude/agents/` 에 사본을 두는 방식은 쓰지 않는다(프로젝트마다 심어야 하고 갈라진다).

**만든 쪽이 자기 영상을 채점하지 않는다.** 별도 agent는 제작 대화의 맥락을 물려받지 않고 남은
산출물만 본다 — ffprobe로 규격과 라우드니스를 재고, 프레임을 뽑아 눈으로 보고, 자막을 대본과
맞춰 본 다음 여섯 항목(technical·visual·audio·narrative·subtitle·fitness)에 1–5점을 매긴다.

agent가 `.claude/memory/<영상 id>.md`의 `## 평가` 절과 프론트매터 `score:`를 직접 채운다.
결과를 받으면 **점수와 "고칠 것"을 사용자에게 그대로 전한다.** 낮은 점수를 감추지 않는다 —
고칠지 말지는 사용자가 정한다.

## 필요한 것

| | 없으면 |
|---|---|
| ffmpeg / ffprobe | 필수. PATH에 있어야 한다 |
| Playwright | 프로젝트 어딘가에 설치. `npm i -D playwright && npx playwright install chromium` |
| edge-tts | `pip install edge-tts` — **API 키 불필요**. 없으면 `--provider sapi`(윈도 내장, 품질 낮음) |
| 실행 중인 앱 | 화면이 안 나온다. 백엔드가 없으면 로딩 스켈레톤이 찍힌다 |

TTS 제공자는 5종이다.

| 제공자 | 키 | 비용 | 쓸 때 |
|---|---|---|---|
| `edge` | 불필요 | 무료 | **기본값.** Edge 읽어주기 엔드포인트 — Azure 뉴럴과 같은 음성 |
| `azure` | `AZURE_SPEECH_KEY`·`AZURE_SPEECH_REGION` | 종량 | 정식 계약이 필요한 납품본 |
| `eleven` | `ELEVENLABS_API_KEY` | **글자수 과금** | 감정 표현이 중요한 강의·내레이션 |
| `sapi` | 불필요 | 무료 | 네트워크가 막힌 환경 (품질 낮음) |
| `file` | — | — | 직접 녹음·촬영한 파일 (인물 PiP와 같은 파일을 쓴다) |

**기본 목소리는 edge다 — 여성은 선희(`ko-KR-SunHiNeural`), 남성은 인준(`ko-KR-InJoonNeural`).**
특별한 음성 언급이 없으면 이걸 쓴다. 사용자가 목소리를 따로 고르지 않으면 `voice`를
`{ "provider": "edge", "lang": "ko", "gender": "female", "rate": "+6%" }`로 둔다 — 이 조합이 선희다.
남성을 골랐으면 `gender`를 `male`, **`rate`를 `+15%`**로 둔다 — 인준은 기본 속도가 느려서
`+15%`라야 선희 `+6%`와 같은 표준 페이스(초당 6.3자)가 나온다(같은 문단 A/B 실측).
새 `scenes.json`을 만들 때 이 블록을 그대로 넣는다.

**초안은 edge로 돌리고, 대본이 확정된 뒤에 유료 제공자로 다시 뽑는다.** 대본은 몇 번씩 고쳐지는데
그때마다 과금되면 아깝다. `--only tts`로 목소리만 먼저 비교할 수 있다.

**azure·eleven은 못 쓰게 되면 자동으로 edge로 내려간다.** 키가 비었거나 만료·결제 중단·크레딧 소진
(401·402·403·429)이면 경고 한 줄을 찍고 남은 씬을 전부 edge로 만든다. 목소리 이름 체계가 달라도
(azure는 `ko-KR-SunHiNeural`, eleven은 계정별 `voice_id`) 전환할 때 각 제공자에 맞는 이름으로 다시
고르므로 `scenes.json`을 고칠 필요가 없다. **설정 잘못(azure 400 SSML, eleven 422 잘못된 목소리·모델)은
폴백하지 않고 그대로 실패한다** — 조용히 내려가면 원인을 못 찾는다.
납품본 목소리를 반드시 고정해야 하면 `voice.strict: true`로 폴백을 끈다.

### ElevenLabs 목소리 — 이름으로 고른다

**id를 코드에 박아 두지 않는다.** 계정마다 보유 목록이 다르므로 `/v1/voices`를 조회해 고른다.
`voice.voice`·`ELEVENLABS_VOICE_ID`에는 **id 대신 이름**을 써도 된다(`"Annie"` → `Annie - Friendly,
Soft and Clear`). 부분 일치로 찾는다.

지정이 없으면 아래 **한국어 기준값** 순서로 계정에서 찾고, 하나도 없으면 성별 라벨로 고른다.

| | 순서 | 쓸 곳 |
|---|---|---|
| 여성 | **Annie** → Kanna → Sola → Park Hyun-mi → Chungman → Hanabad | Annie=강의·매뉴얼 · Kanna=홍보·쇼츠 · Sola=내레이션 · Park Hyun-mi=신뢰감 · Chungman=느린 학습 |
| 남성 | **Taehyung** → Hojin Lim → Harry Kim → Juan | Taehyung=강의·튜토리얼 · Hojin Lim=제품 소개 · Harry Kim=인터뷰 톤 · Juan=다큐·생애사 |

**보이스 라이브러리(탐색) 목소리는 "내 음성"에 추가해야 API로 잡힌다.** 추가 전에는 `/v1/voices`에
안 나오고 이름도 못 찾는다. 못 찾으면 계정에 있는 이름을 나열해 주므로 그걸 보고 고르면 된다.

**목소리는 대본을 쓰기 전에 귀로 정한다.**

```bash
node tools/video/check-tts.js --list-voices          # 보유 목록 + id (글자 소모 없음)
node tools/video/check-tts.js --sample-voices 8      # 같은 문장을 8개 목소리로 (기준값 순서로)
node tools/video/check-tts.js --sample-voices 5 --sample-text "오늘은 로그인 화면을 만들어 봅니다."
```

만든 샘플은 한 폴더에 모이고 `ffplay` 명령까지 찍어 준다. 크레딧 잔량도 함께 보여 주므로
얼마 쓰는지 보고 결정할 수 있다(샘플 8개 × 15자 = 120자 안팎).

기타 기준값: 모델 `eleven_multilingual_v2` · `stability` 0.5 · `similarity` 0.75.
`scenes.json`의 `voice`에서 덮어쓴다.

## 사람이 나오는 영상

씬마다 한 컷씩 찍어 `presenter/<영상 id>/<씬id>.mp4`로 넣으면 **같은 파일이 음성과 인물 영상
양쪽으로** 쓰인다.

```json
"voice":     { "provider": "file", "fallback": "edge" },
"presenter": { "enabled": true,
               "size": 0.22, "align": "bottom-right",
               "zoom": 0.6, "focusX": 0.4, "focusY": 0.05 }
```

**`dir`은 쓰지 않는다 — 영상 id로 자동으로 갈린다.** 비워 두면 `presenter/<영상 id>/`를 본다.
예전에는 기본값이 `presenter/` 통짜라 저장소의 모든 영상이 한 폴더를 씬 id만으로 뒤졌고, 두
영상에 `intro` 씬이 있으면 **뒤에 만든 영상이 앞 영상의 촬영분을 말없이 집어 갔다**(합성은 그대로
성공한다 — 재생해 보기 전에는 모른다). 지금은 `out/<영상 id>/`처럼 입력도 자동으로 갈린다.

굳이 `dir`을 지정하면 그 값이 그대로 쓰이는데, 영상 id가 경로에 없으면 0단계 사전 점검이
경고한다 — 여러 영상이 한 폴더를 공유하는 상태를 굽기 전에 알려 준다.

`zoom`·`focus*`는 **거의 항상 조정이 필요하다** — 얼굴은 보통 화면 위쪽에 있어서 그냥 가운데를
자르면 원 안이 책상·가슴으로 찬다. 말하지 않는 컷은 사진(png/jpg)도 되며 느린 줌이 걸린다.

## 소재 (BGM · 인물 클립 · 사진 · B롤)

`assets/`에 받아 두고 여러 프로젝트에서 재사용한다. **파일 자체는 git에서 제외된다** —
무료 스톡은 "프로젝트에 사용"은 허용해도 소재 파일의 재배포는 대부분 금지하기 때문이다.
커밋되는 것은 목록(`assets/CATALOG.md`)과 받아오는 도구(`assets/fetch.js`)뿐이다.

```bash
node assets/fetch.js bgm   <직접링크> [파일명]   # assets/bgm/ 에 저장
node assets/fetch.js clip  <직접링크> [파일명]   # assets/presenter/ 에 저장
node assets/fetch.js photo <직접링크> [파일명]   # assets/photo/ — photo.html 배경
node assets/fetch.js broll <직접링크> [파일명]   # assets/broll/ — 클립 video 소스
node assets/fetch.js list
```

사진·B롤을 고를 때는 **직접 링크**가 필요하다 — Pexels·Pixabay 페이지에서 다운로드 버튼의 URL을
쓴다(검색 API는 키가 필요해서 붙이지 않았다). 소재 검색은 사람이 하고, 받는 것과 기록만 도구가 한다.

허용 호스트(Mixkit·Pexels·Pixabay·Coverr)가 아니면 받지 않는다. 받은 뒤에는 출처와 라이선스를
`CATALOG.md`에 기록한다.

`scenes.json`에서 **영상 작업 폴더 기준 상대 경로**로 가리킨다.

```json
"bgm": "../../.claude/skills/develop-video/assets/bgm/<파일>.mp3",
"bgmGain": 0.18,
"bgmDucking": true
```

`bgmDucking`은 내레이션이 나올 때 배경음을 자동으로 눌러 준다(사이드체인). 일정 볼륨으로 깔면
말과 배경음이 같은 대역에서 싸워 대사가 묻힌다. 기본값은 켬.

**곡 선택은 사람이 한다.** 자동으로 고르지 말고 후보를 받아 `ffplay`로 들려주고 고르게 한다.
매뉴얼 영상은 BGM을 아예 빼거나 아주 낮게(0.08 안팎) 까는 편이 낫다.
**강의는 "낮게(0.08)"가 안전한 기본값이다** — 내레이션 집중 때문에 빼고 싶어지지만, BGM 이
없으면 TTS 의 문장 간 호흡(1.2~1.4초)이 전부 무음으로 노출되어 러닝타임의 30%가 정적이
될 수 있다(실측 사례: 4분 51초 강의에서 71건·93초). 사용자가 "없음"을 고르면 이 트레이드오프를
1단계 질문의 선택지 설명에 한 줄로 밝혀 준다.

## 지켜야 할 선

- **유튜브 등에서 영상을 내려받아 쓰지 않는다.** 이용약관 위반이고 저작권·초상권 문제가 된다.
  무료 스톡(Mixkit·Pexels·Pixabay)은 상업적 사용이 허용되며 다운로드도 정식으로 제공된다.
- **실존 인물의 얼굴을 동의 없이 쓰지 않는다.** 본인이거나 라이선스가 있는 소재여야 한다.
- **얼굴이 식별되는 스톡 인물을 특정 서사의 당사자로 쓰지 않는다.** "스무 살의 나"에 모델 사진을
  깔면 라이선스와 무관하게 보는 사람을 오해시킨다. 뒷모습·손·풍경·사물·실루엣을 쓴다.
- **BGM은 라이선스가 확인된 음원만.** 임의 음원은 수익화·노출에서 막힌다.
- **없는 기능을 내레이션에 넣지 않는다.** 광고 문구는 저장소에 근거가 있어야 한다.

## 산출물 — 영상 한 편이 폴더 하나

**영상 한 편(대본 하나)이 `out/<영상 id>/` 하나를 차지한다.** 한 저장소에서 홍보·매뉴얼·릴리스
노트를 같이 만들어도 서로 덮어쓰지 않고, 지난 영상을 다시 뽑을 때 그 폴더만 있으면 된다.

```
tools/video/out/
  <영상 id>/
    final/     <변형>.mp4   완성본 (H.264 High / yuv420p / AAC-LC / +faststart, -14 LUFS)
               <변형>.srt   자막 사이드카 (유튜브 업로드용)
    raw/       take.webm      통짜 원본 — 재합성에 쓰이므로 지우지 않는다
               timeline.json  씬 경계
    audio/     씬별 음성 + manifest.json   (TTS 캐시)
    motion/    모션·B롤 렌더 결과          (캐시)
    work/      ass·무음·마스크 등 중간물   (언제든 지워도 된다)
    frames/    검증용 프레임 캡처
```

**넘길 것은 `final/` 하나뿐이다.** `raw/`는 재촬영 없이 다시 합성하려면 필요하니 지우지 않는다.
용량이 급하면 `work/`부터 지운다 — 다음 실행에서 다시 만든다.

**기록은 따로 산다.** `out/`은 산출물이고, 어떻게 만들었고 결과가 어땠는지는 저장소에 남긴다.

```
.claude/memory/
  README.md          형식 규약
  <영상 id>.md        제작 기록(8단계) + 평가 점수(9단계, agent가 채운다)
```

`out/`은 용량 때문에 언제든 지워질 수 있지만 기록은 git에 남는다. **id는 양쪽을 잇는 유일한
열쇠이니 반드시 일치시킨다.**

### 두 편을 동시에 만들 수 있다

**중간물까지 전부 영상별 폴더 안에서 논다.** 그래서 id만 다르면 두 작업을 나란히 돌려도 섞이지 않는다.

```bash
node tools/video/build.js --project promo  &
node tools/video/build.js --project manual &
wait
```

`--project <id>`는 `projects/<id>/scenes.json`을 알아서 찾는다(`--scenes`를 주면 그쪽이 우선).

| 무엇이 | 어디에 |
|---|---|
| TTS 음성·캐시 | `out/<id>/audio/` |
| 모션·B롤 렌더 | `out/<id>/motion/` |
| Playwright 임시 녹화본 | `out/<id>/work/playwright/` |
| ffmpeg 실행 위치(cwd)·ass·무음 | `out/<id>/work/` |
| 완성본 | `out/<id>/final/` |

전역으로 공유되는 것은 **읽기 전용**뿐이다 — 스크립트, `templates/motion/`, `assets/`, `.env`.
쓰는 경로는 하나도 겹치지 않는다.

**지켜야 할 선 셋.**

- **같은 id를 동시에 두 번 돌리지 않는다.** `--project`가 같으면 같은 폴더를 쓴다. id를 나눠라.
  두 번째 실행은 `out/<id>/.lock`에 걸려 시작 전에 끊긴다 — 예전에는 둘 다 "완료"를 찍고
  깨진 mp4가 나왔다. 강제로 종료해 잠금이 남았으면 다음 실행이 알아서 이어받는다.
- **같은 앱을 동시에 녹화하지 않는다.** 파일은 안 겹쳐도 앱의 상태(로그인·생성한 데이터)가 섞인다.
  화면 녹화가 있는 작업 둘은 순서대로 돌리거나, 서로 다른 포트에 앱을 띄워 `--base-url`을 나눈다.
  **모션·사진 전용 영상(`scenes: []`)은 앱을 안 건드리므로 마음껏 병렬로 돌려도 된다.**
- **작업 하나당 Chromium 1개 + ffmpeg 1개**를 쓴다. 4K나 긴 영상 여러 개를 한꺼번에 돌리면
  CPU·메모리가 먼저 바닥난다. 둘 정도가 적당하다.

영상 id는 이 순서로 정해진다.

| 순서 | 출처 | 예 |
|---|---|---|
| 1 | `--project <id>` | `--project release-2025-08` → `out/release-2025-08/` |
| 2 | `scenes.json`의 `"id"` | `"id": "onboarding-manual"` |
| 3 | 대본 파일 이름 | `scenes.json` → `default`, `scenes.promo.json` → `promo` |

한글 이름도 그대로 폴더가 된다(`--project "사용 매뉴얼"` → `out/사용-매뉴얼/`). 공백·슬래시는
하이픈으로 바뀐다. 여러 편을 만들 때는 **`projects/<id>/` 폴더를 나눈다** — 폴더 이름이 곧
id 가 되어 `--project` 하나로 대본·산출물이 다 갈린다(5단계 규약 참조).
