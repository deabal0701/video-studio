# 강좌 영상 제작 — 일관성이 제품이다

유튜브 강좌는 한 편이 아니라 **시리즈**다. 구독자는 회차마다 달라지는 참신함이 아니라
**같은 틀이 반복되는 것**을 신뢰로 읽는다 — 같은 오프닝, 같은 목소리, 같은 색, 같은 리듬.
어느 회차를 틀어도 3초 안에 "그 강좌"임을 알아보게 만드는 것이 이 스킬의 일이다.

그래서 원칙은 하나다. **강좌 정체성은 `course.json` 한 곳에만 적고, 회차는 그것을 그대로
상속한다.** 회차를 만들 때 목소리·색·오프닝을 다시 정하지 않는다 — 정할 것이 없어야
일관성이 지켜진다.

## 회차는 독립이다 — 어느 편을 먼저 봐도 된다

**시리즈지만 연속물이 아니다.** 시청자는 검색·추천으로 아무 회차에나 도착하고, 그 한 편만 보고
떠날 수도 있다. 그래서 **모든 회차는 그 편 하나로 완결**되어야 한다 — 회차 번호는 정렬용이지
수강 순서가 아니다.

| 금지 | 대신 |
|---|---|
| "1강에서 배웠듯이" · "지난 시간에" · "1강을 떠올려 보죠" | 필요한 배경은 **그 자리에서 한 문장으로** 다시 세운다 — "챗지피티는 다음에 올 말을 확률로 고릅니다. 이걸 알고 계시면 오늘 이야기가 쉽습니다" |
| 앞 회차를 안 보면 이해가 막히는 구성 | 그 회차 안에서 전제 → 본론 → 회수가 닫힌다 |
| "다음 강에서 다룹니다" (예고) | 그 회차에서 다룰 만큼만 다루고 조용히 끝낸다(아웃트로 규칙과 동일) |
| plan.md 의 대상을 "N강을 본 사람" 으로 잡는 것 | 대상은 언제나 **"이 주제어를 들어는 봤지만 설명은 못 하는 직장인"** |

**배경 지식을 다시 세우는 비용은 한 문장~두 문장이다.** 그 비용이 아까워서 앞 회차에 기대면,
검색으로 들어온 시청자(대다수)가 첫 30초에 나간다. 반대로 잘 세워 두면 그 시청자가 **다른
회차를 찾아본다** — 시리즈는 그렇게 커진다.

같은 개념이 여러 회차에 나오는 것은 **중복이 아니라 설계**다. 매번 같은 한 문장으로 세우면
반복 시청자에게는 각인이 되고 신규 시청자에게는 입장권이 된다.

시리즈 연결은 영상 밖이 맡는다 — 재생목록 · 유튜브 종료화면 · 설명란 링크(업로드 뒤에도
고칠 수 있는 곳).

## develop-video 와의 관계

제작 그 자체(구성표 → 대본 → 도식 → 빌드 → 검증 → 평가)는 **전부 develop-video 스킬의
5~9단계를 그대로 따른다.** 대본 문법은 그쪽 `references/authoring.md`, 도식·타이밍·검증
규칙도 그쪽이 원전이다. 이 스킬이 정하는 것은 그 위의 두 가지뿐이다:

1. **무엇을 고정하는가** — 강좌 정체성(아래 표)
2. **유튜브에 올릴 준비물** — 챕터 타임스탬프·설명란·썸네일

develop-video 의 1단계(질문 라운드)는 **강좌 개설 때 한 번만** 한다. 회차 제작에서는 묻지
않는다 — 답이 이미 course.json 에 있다.

## 고정하는 것 vs 회차마다 바꾸는 것

| 고정 (course.json — 시리즈 내내) | 가변 (회차마다) |
|---|---|
| **편당 길이 — 5분 안팎** (아래 분량 규칙) | 회차 주제·제목 |
| 목소리·페이스 (선희 `+8%` 또는 인준 `+19%`) | 훅·대본·도식 |
| **오프닝 순서 — B롤 → 제목 카드 → 훅 → 시그니처** (아래 "인트로" 절) | 회차 전용 도식 html |
| course-stinger 시그니처 3초 (강좌명 + 태그라인 — 회차 정보 없음) | 인트로 B롤 소재(회차 주제에 맞게) |
| course-intro 타이틀 카드 형식 (강좌명 + n강 + 회차 제목) | |
| 브랜드 색 (`background`·`brand`·`brandText`) | 챕터 수·구성 |
| 워터마크 = 강좌명 | |
| BGM 곡 + `bgmGain 0.08` + 더킹 | |
| 회차 골격 (B롤 → 타이틀 → 훅 → 시그니처 → 약속 → 챕터×N → 정리 → 아웃트로) | |
| 아웃트로 형식 (한 줄 각인 + 인사 — **다음 강 예고는 넣지 않는다**) | |
| **화면 소재 — 실사 영상(B롤)은 회차당 최대 1개**, 설명은 전부 도식·모션·데이터 흐름 | |

## 목소리 — 선희 또는 인준, 조금 빠르게

강좌는 **표준(초당 6.3자)보다 한 단계 빠른 페이스**를 기본으로 한다 — 초당 약 6.4자,
5분 ≈ 1,900자. 강의는 반복 시청과 배속 시청이 많아 살짝 빠른 쪽이 덜 늘어진다.
아래 rate 는 같은 문단 A/B 실측으로 두 목소리의 페이스를 맞춘 값이다(0.5% 차이).

| 목소리 | 설정 | 페이스 |
|---|---|---|
| 선희 (여성) | `{ "provider": "edge", "lang": "ko", "gender": "female", "rate": "+8%" }` | ≈6.4자/초 |
| 인준 (남성) | `{ "provider": "edge", "lang": "ko", "gender": "male", "rate": "+19%" }` | ≈6.4자/초 |

강좌 개설 때 하나를 고르면 **시리즈 내내 바꾸지 않는다.** 분량 배분(plan.md)도 6.4자/초로
계산한다.

## 분량 — 5분 개념강좌

이 스킬이 만드는 강의는 **5분 안팎의 개념강좌**다. 개념 하나를 5분에 세우는 것이 형식의
정체성이고, 회차 길이가 들쭉날쭉하면 "5분 강좌"라는 약속 자체가 깨진다.

| | |
|---|---|
| 내레이션 예산 | **약 1,850자** (6.4자/초 × 290초 — 클립 여유 0.5초×12개와 무음 타이틀 몫을 뺀 값) |
| 완성본 허용 범위 | **4분 40초 ~ 5분 20초** |
| 확인 시점 | 대본 초안 직후 `--only tts` 실측 (완성하고 재는 것은 늦다 — develop-video 5단계 규약) |

실측이 범위를 벗어나면:

- **모자라면** 문장을 늘리지 말고 **내용을 더한다** — 일상 예시 하나, 반문 하나, 시청자가
  실제로 물을 질문 하나. (rest-api-lecture 가 이 방식으로 255초→291초를 채웠다.)
- **넘치면 회차를 쪼갠다.** 5분에 안 들어가는 주제는 압축할 것이 아니라 **다음 강**이다 —
  커리큘럼(course.json 의 episodes)에 한 편을 끼워 넣는 것이 시리즈에는 오히려 이득이다.
  문장 압축으로 20초 안쪽을 줄이는 것까지만 허용한다.
- 내레이션에 "5분"이라는 숫자를 박지 않는다 — 실측 전의 목표치가 화면에서 거짓이 될 수 있다.

## 흐름

### 1. 강좌 개설 — 한 번만 묻는다

AskUserQuestion 한 라운드(최대 4문항, 요청에 이미 있는 것은 빼고):

1. **강좌명·대상** — 워터마크와 타이틀 카드·시그니처 인트로에 그대로 들어간다.
   **태그라인(인트로 한 줄)은 묻지 않고 강좌명에서 만들어 제안하고 8단계 보고에 싣는다** —
   질문 한 라운드를 늘리는 것보다 낫고, 바꾸기도 쉽다(`--only compose` 몇 초)
2. **회차 구성** — 몇 강, 회차 제목까지 받으면 커리큘럼이 된다. 편당 길이는 묻지 않는다 —
   5분 개념강좌가 이 스킬의 형식이다(위 분량 규칙). 사용자가 다른 길이를 명시했을 때만 따른다
3. **목소리** — 선희 / 인준 (위 표의 rate 로 고정)
4. **브랜드 색** — 기본 `#3E63DD` 계열 / 지정 색

받으면 강좌 폴더를 만든다:

```
tools/video/projects/<강좌id>/          # 강좌 공통 — 회차 폴더가 참조한다
  course.json                           # 강좌 정체성 (templates/course.json 복사해 채움)
  course-stinger.html                   # 시그니처 인트로 3초 (templates/ 에서 복사 — 회차마다 동일)
  course-intro.html                     # 오프닝 타이틀 카드 (templates/ 에서 복사)
tools/video/projects/<강좌id>-01/       # 1강 = 영상 한 편 (develop-video 규약 그대로)
  scenes.json  plan.md  <회차 전용 도식>.html
  bg/<B롤파일>.jpg                      # 타이틀 카드 배경 — 그 회차 B롤에서 뽑은 프레임
```

`<강좌id>-NN` 이 develop-video 의 영상 id 다 — `--project <강좌id>-01` 로 빌드하고
산출물은 `out/<강좌id>-01/` 에 떨어진다.

### 2. 회차 제작 — develop-video 5~9단계 그대로

`templates/episode.scenes.json` 을 회차 폴더에 복사하고 course.json 값을 채운 뒤,
**develop-video 5단계(구성표부터)로 들어간다.** 회차 골격은 이 순서를 지킨다:

| 구간 | 무엇 | 규격 |
|---|---|---|
| **broll** | **영상의 첫 화면 — 회차 주제의 실사 B롤.** 시청자가 "무엇에 대한 영상인지" 0.5초 안에 감지한다 | **2초 · 무내레이션**(BGM 만). `video` + `shade: 0.35`. **회차당 허용된 실사 1개를 여기에 쓴다** |
| **title** | `../<강좌id>/course-intro.html` — **앞 B롤과 같은 소재 위에** 강좌명·n강·회차 제목이 얹힌다 | B롤 **직후**, **4초.** `src` 에 **앞 B롤에서 뽑은 프레임**을 넘긴다(아래 "인트로" 절). 실사가 그대로 정지하며 제목이 올라오는 것처럼 이어져, 컷이 갈리지 않는다 |
| hook | 회차 주제의 구체적 장면·반전 — 본론의 문을 여는 컷(도입부가 성패를 가르면 develop-video 4단계 컨셉 검증) | 임팩트는 파격적 문구가 아니라 **구체적 장면의 반전**이다. 정답 라벨을 반전 전에 공개하지 않는다. 제목이 이미 나왔으므로 훅은 "주제 소개"가 아니라 **"왜 이걸 봐야 하나"** 만 담당한다 |
| **stinger** | `../<강좌id>/course-stinger.html` — **강좌 시그니처 인트로.** 회차마다 **한 프레임도 다르지 않게** 반복되는 브랜드 스팅어 | **3초 고정 · 내레이션 없음**(BGM 만). 훅 **뒤**. 여기서 "이 강좌구나"가 각인된다. 아래 "인트로" 절 참조 |
| promise | "오늘 얻어갈 것" 약속 한 컷 — 이것이 목차다 | 훅이 연 궁금증을 3~4개 항목의 약속으로 받는다(예: "동사·주소·대답, 이 세 조각을 읽습니다"). **목차를 먼저 보여주는 것은 스포일러다** — 상세 목차는 챕터 카드와 유튜브 챕터가 담당한다. 배경 지식이 필요하면 **여기서 한 문장으로 세운다**("챗지피티는 다음 말을 확률로 고릅니다") — 앞 회차를 안 본 시청자의 입장권이다 |
| chN + sN | 챕터 카드 + **도식** (글자 카드로 때우지 않는다 — develop-video 규칙) | 도식 등장 시각은 내레이션 발화 시각에 동기화 |

**화면 소재 규칙 — 실사 영상(B롤)은 회차당 1개, 그리고 그 자리는 인트로다.**
오프닝 B롤 하나를 쓰고 나면 **설명하는 구간은 전부 직접 그린 도식·모션 애니메이션**으로 채운다.
개념은 움직임이 설명한다 — "소리를 끄고 봐도" 이해되는 것이 합격선이다(develop-video
7단계). B롤은 아무리 좋은 소재라도 개념을 1초도 설명하지 못하므로, B롤이 두 개 이상
있으면 그 회차는 설명이 비어 있다는 신호로 읽는다.

**연출 팔레트 — 설명의 종류가 기법을 고른다.** 전부 CSS 키프레임(고정 지연)으로 그린다 —
렌더러가 스크럽 방식이라 rAF·JS 물리는 못 쓴다(develop-video authoring.md).

| 설명하려는 것 | 기법 | 구현 |
|---|---|---|
| 이동·전달 (요청이 서버로 간다, 데이터가 흐른다) | **데이터 흐름** — 점·봉투가 선을 따라 이동, 화살표가 자란다 | `transform: translate` · `scaleX` 키프레임 |
| 세부로 파고들기 (전체 → 이 부분을 자세히) | **줌 인** — 전체 그림에서 한 부분이 커지며 중앙으로 | 컨테이너 `transform: scale()+translate` 키프레임. 배율 2~3배, 0.6~0.9초 |
| 전체 구조로 물러나기 (부분들 → 큰 그림) | **줌 아웃** — 세부에서 시작해 전체 배치가 드러남 | 위와 반대 방향. 훅→약속 전환에 잘 맞는다 |
| 수치 비교·추세 (몇 배 차이, 늘어난다/줄어든다) | **그래프** — 막대가 자라고, 선이 그려진다 | 막대: `scaleY`(transform-origin bottom) · 선: SVG `stroke-dashoffset` 키프레임. 눈금·단위를 붙여야 그래프다 — 수치 출처는 저장소 근거(develop-video 규칙) |
| 구조·계층 (층이 쌓인다, 무엇이 어디 속하나) | 상자가 **쌓이고** 색으로 갈린다 | cloud-layers.html 선례 |
| 상태 변화 (생성·복제·삭제) | 요소가 **나타나고·복제되고·부서진다** | rest-delete.html(조각 낙하)·cloud-replica.html 선례 |

한 도식에 기법 하나가 원칙이다 — 줌하면서 그래프가 자라면 시선이 갈 곳을 잃는다.
필요한 그림이 선례에 없으면 새 html 을 그린다 — rest-api-lecture 는 일곱 장 전부 새로
그려서 5분을 채웠다.
| recap | 정리 — 배운 것이 내레이션 순서로 **쌓이는** 도식 | rest-api-lecture 의 `rest-outro.html` 패턴 |
| outro | 회차의 한 줄 각인 + 인사 | **다음 강 예고를 영상에 굽지 않는다** — 다음 회차는 수시로 바뀔 수 있고, 구워 둔 예고는 커리큘럼이 바뀌는 순간 거짓이 되며 고치려면 재합성이다. 시리즈 연결은 업로드 뒤에도 수정되는 곳이 맡는다: 재생목록·유튜브 종료화면·설명란 링크 |

톤은 차분하게, 구조는 공격적으로 — 임팩트는 볼륨이 아니라 궁금증에서 나온다. 목소리·BGM은
강좌 설정 그대로 두고 첫 3초의 화면과 반전 타이밍으로 승부한다. 제목·썸네일 카피도 같은
원리다: 추상적 파격("충격적인 진실")은 낚시로 읽히고 **시리즈는 낚시에 제일 취약하다** —
1강에서 낚였다고 느낀 시청자는 2강을 안 본다. "한 줄로 사람이 지워집니다"처럼 영상이 실제로
보여줄 구체 장면을 약속한다.

### 인트로 — 영상 → 제목 → 훅 → 시그니처

**첫 5초의 순서가 정해져 있다.** 실사 B롤로 열고, 제목 카드로 무엇을 보는지 알려 준 뒤,
훅으로 볼 이유를 만들고, 시그니처 스팅어로 강좌를 각인한다.

| 순서 | 무엇 | 길이 | 왜 여기인가 |
|---|---|---|---|
| 1 | **B롤** (회차 주제 실사, 무내레이션) | 2s | 0.5초 안에 "무엇에 대한 영상인지" 감지된다. 도식은 읽어야 알지만 실사는 보면 안다 |
| 2 | **제목 카드** (course-intro — **같은 소재 위**) | 4s | 앞 영상이 그대로 정지하며 제목이 올라온다. **제목이 5초 안에** 나오고 컷도 갈리지 않는다 |
| 3 | **훅** (본론의 첫 장면) | 3~4s | 제목이 이미 나왔으니 훅은 주제 소개가 아니라 **"왜 봐야 하나"** 만 담당한다 |
| 4 | **시그니처 스팅어** (course-stinger) | 3s 고정 | 볼 이유가 생긴 뒤에 "이 강좌구나"를 각인한다 |

**영상과 제목을 잇는 법 — 같은 소재의 프레임을 카드 배경에 깐다.** `video` 클립과 html
카드는 같은 구간에 겹칠 수 없다(렌더러가 `document.getAnimations()` 만 밀어 `<video>` 가
첫 프레임에서 얼어붙는다 — develop-video `authoring.md`). 그래서 **B롤에서 프레임 한 장을
뽑아** `course-intro.html` 의 배경으로 넘긴다. 카드에 걸린 켄번즈 줌이 계속 움직여서
화면에서는 영상이 그대로 흐르는 것으로 읽힌다.

```bash
# ① B롤에서 배경 프레임을 뽑는다 — videoStart 와 같은 시각을 쓴다
mkdir -p tools/video/projects/<강좌id>-NN/bg
ffmpeg -y -ss 3 -i .claude/skills/develop-video/assets/broll/<파일>.mp4 \
  -frames:v 1 -vf scale=1920:-1 tools/video/projects/<강좌id>-NN/bg/<파일>.jpg
```

```json
{ "id": "broll", "video": "../../.claude/skills/develop-video/assets/broll/<파일>.mp4",
  "videoStart": 3, "shade": 0.35, "duration": 2.0, "before": "end" },
{ "id": "title", "file": "../<강좌id>/course-intro.html", "duration": 4.0, "before": "end",
  "narration": "1강, 챗지피티의 심장, 엘엘엠입니다.",
  "params": { "src": "../<강좌id>-NN/bg/<파일>.jpg", "kicker": "<강좌명>", "num": "1강",
              "title": "<회차 제목>", "subtitle": "<부제>", "shade": "0.55", "wipe": "off" } }
```

**두 가지를 반드시 맞춘다 — 둘 다 오류를 내지 않고 조용히 망가진다.**

| 맞출 것 | 틀리면 |
|---|---|
| **`videoStart` = 프레임을 뽑은 시각** | 영상이 끝나는 순간 배경이 튀어 "정지하며 이어진다"가 깨진다 |
| **`src` 는 `course-intro.html` 기준 상대 경로** | 이미지가 **조용히 빠진 채**(오류 없이 검은 배경) 완성된다 |

`src` 가 특히 함정이다. 카드 html 은 `projects/<강좌id>/` 에 있고 브라우저가 **그 파일 기준**
으로 이미지를 찾으므로, 회차 폴더의 `bg/` 를 가리키려면 **한 단계 올라가야** 한다 —
`bg/…` 가 아니라 `../<강좌id>-NN/bg/…`. 사전 점검은 `params` 이름만 보고 그 값이 가리키는
파일이 있는지는 모른다. **빌드 뒤 타이틀 프레임을 반드시 눈으로 확인한다.**

**B롤 고르기** — `assets/broll/` 의 보유분에서 회차 주제에 맞는 것을 고른다(스톡 검색 API 는
붙어 있지 않다). 고를 때 보는 것: ① 주제와 결이 맞는가 ② **가운데가 비어 있는가**(제목이
화면 중앙에 선다) ③ 1080p 이상인가. `videoStart` 는 프레임을 뽑아 보고 정한다.
`shade` 는 B롤 클립 **0.35** · 제목 카드 **0.55** — 카드 쪽을 더 눌러야 제목이 읽힌다.
소재가 밝으면 카드 `shade` 를 0.7까지 올린다.

**소재 색이 강좌 색과 달라도 된다** — 카드의 브랜드 광원(`.tint`)이 색조를 강좌 쪽으로
당겨 준다. 금색 소재에 파란 강좌 색을 얹어도 시리즈로 보인다.

**확정 표본이 스킬 안에 있다 — 새 강좌는 여기서 시작한다.**
`templates/reference.scenes.json` 이 이 인트로 구성을 20초로 압축한 **실제로 빌드되는**
대본이다(B롤 → 제목 → 스팅어 → 본론 → 마무리). 강좌를 새로 열 때는 이 파일을 먼저 읽어
구간 길이·`shade` 값·`params` 이름을 확인한다 — 글로 적힌 규격보다 **돌아가는 대본 한 장**이
어긋남을 빨리 잡는다. 스타일을 바꾸고 싶으면 이 표본을 고쳐 빌드해 보고, 결과가 좋으면
그때 `course-intro.html` 과 이 문서를 함께 고친다.

**실사는 여기서만 쓴다.** 회차당 허용된 실사 1개를 인트로에 쓰므로, **설명 구간은 예외 없이
도식**이다(아래 화면 소재 규칙). B롤이 인트로 밖에 또 있으면 그 회차는 설명이 비어 있다는 신호다.

#### 시그니처 3초는 회차마다 똑같아야 한다

강좌의 얼굴은 타이틀 카드가 아니라 **매 회차 반복되는 짧은 스팅어**다. 구독자는 이 3초를
눈이 아니라 몸으로 기억하고, 그래서 **바뀌면 안 된다** — 회차마다 다른 인트로는 시리즈가
아니라 낱개 영상 모음으로 읽힌다.

`templates/course-stinger.html` 을 강좌 개설 때 `projects/<강좌id>/` 로 복사하고, 회차는
그대로 참조한다.

| | |
|---|---|
| 길이 | **3초 고정** (`duration: 3.0`). 10초를 넘기지 않는 것이 아니라 **3초를 지킨다** — 회차마다 반복되는 구간이라 1초만 길어도 재시청자가 건너뛴다 |
| 소리 | **내레이션 없음.** BGM 만 흐른다 — 매번 같은 말을 듣는 것만큼 빨리 질리는 것이 없다 |
| 자리 | **훅 뒤 · 약속(promise) 앞.** 첫 화면은 B롤이고 제목이 5초 안에 나온 뒤 훅이 볼 이유를 만든다 — 스팅어는 그 다음이다(위 "인트로" 절의 4단계) |
| params | `brandline`(강좌명 — 워터마크와 같은 문구) · `tagline`(한 줄, 선택) · `wipe: "off"` |
| 넣지 않는 것 | **회차 번호·회차 제목·다음 강 예고.** 그건 뒤따르는 course-intro 타이틀 카드의 몫이다 — 스팅어에 회차 정보가 들어가면 회차마다 달라져 "똑같이 반복"이 깨진다 |

연출은 **한 점에서 시작해 넓어지는** 은유다 — 브랜드 점이 떨어져 눌리며 파문이 퍼지고,
그 파문에서 가로선이 양쪽으로 자라 강좌명이 선 위로 올라선 뒤 태그라인이 붙는다.
개념강좌(하나의 개념에서 이해가 번진다)와 결이 맞고, 색은 `course.json` 의 브랜드 색을
그대로 쓰므로 강좌마다 자동으로 달라진다.

**태그라인은 강좌 개설 때 한 번 정하고 바꾸지 않는다** — 강좌명을 보조하는 한 줄이면 된다
(예: "개념 하나를, 5분에"). 광고 카피처럼 쓰지 않는다.

### 깊이 — 내용은 회의 상식, 용어는 정확하게

시청자는 회차 주제어를 이미 들어봤다(뉴스·회의·유튜브 — 직장인에게 LLM·금리·애자일은
낯선 말이 아니다). "OO란 무엇인가"를 순한 정의 반복으로만 채우면 아는 얘기로 읽혀 이탈한다.
그렇다고 논문·수식·내부 구조로 들어가면 **전공 강의**가 되어 대상을 잃는다.

**과녁은 하나다 — 회의나 미팅에서 이 주제가 나왔을 때 흐름을 놓치지 않고 한마디 보탤 수
있는 수준.** 그 이상은 이 강좌의 몫이 아니다.

| 이 강좌가 하는 것 | 이 강좌가 하지 않는 것 |
|---|---|
| **개념 하나**를 업무 장면으로 세운다 | 여러 개념을 한 회차에 욱여넣기 |
| 정식 용어를 **정확히 부르고 즉시 푼다** | 용어를 정의만 하고 지나가기 |
| "그래서 실무에서 이렇게 읽힌다"까지 | 내부 동작·수식·아키텍처 해부 |
| 출처 있는 사실 한 조각 | 논문 여러 편의 비교·계보 정리 |

**용어는 전문적으로, 설명은 회의 언어로.** 이 둘은 충돌하지 않는다 — 오히려 짝이다.
회의에서 꺼낼 수 있는 것은 비유가 아니라 용어이고, 그 용어를 **동료에게 한 문장으로 풀어
줄 수 있을 때** 비로소 아는 것이 된다.

- **정식 용어는 회차당 3~4개까지.** 화면에 라벨로 박고 **바로 다음 문장에서 일상어로 푼다**
  (순서는 언제나 "용어 → 즉시 풀이"). 5개를 넘어가면 회차가 용어 목록이 되고 하나도 안 남는다.
  용어를 고를 때는 **"이 말이 회의에서 실제로 오가는가"** 를 기준으로 한다 — 오가지 않는
  내부 용어(어텐션 헤드·소프트맥스 같은)는 뺀다.
- **한 걸음 더 조각은 회차당 하나.** 아는 사람만 아는 심화 한 조각 — 연도·출처가 있는 역사,
  업계가 실제로 쓰는 구분, 흔한 오해의 정확한 교정. **facts.md 에 근거가 있는 것만**,
  그리고 **한 조각이면 충분하다.** 둘 이상 넣으면 회차의 결이 강의에서 논문 브리핑으로 바뀐다.
- **수치는 회차당 한 쌍까지.** 반전 수치는 강력하지만 여러 개가 나오면 시청자가 아무것도
  기억하지 못한다. 시점·모델·출처 한정을 붙여 **하나만** 세운다.
- **recap 은 용어로 잠근다** — 정리 도식에 일상어 풀이와 **정식 용어를 병기**해 "오늘 배운 말"
  자체가 산출물이 되게 한다(예: "다음 단어 맞히기 = 다음 토큰 예측").
- **금지 — 효용을 선언하지 않는다.** "이제 아는 척할 수 있습니다", "어디 가서 아는 체하세요"류의
  메타 문구를 내레이션·화면·제목에 쓰지 않는다. 지식의 효용은 내용의 깊이가 증명하는 것이지
  말로 다는 것이 아니다 — 다는 순간 강의가 얕아 보인다.

**자문 한 줄로 점검한다 — "이 문장을 회의에서 소리 내어 말할 수 있나?"** 말할 수 없는 문장
(내부 구조 설명, 논문 인용 나열, 수식)은 회차에서 뺀다. 말할 수 있는 문장만 남기면
그 회차는 자동으로 이 강좌의 눈높이에 맞는다.

#### 용어 주석 — 약어가 나오면 화면이 원어와 뜻을 대신 알려 준다

**TTS 는 영문 약어를 소리 나는 대로 읽고, 자막도 그대로 나간다.** "LLM"은 «엘엘엠», "API"는
«에이피아이», "ETF"는 «이티에프»로 자막에 찍힌다. 그 자막만 본 시청자는 **그 말을 검색할
수도, 회의에서 정확히 꺼낼 수도 없다** — 철자를 모르기 때문이다. 용어를 정확히 부른다는
원칙이 자막 단계에서 무너지는 지점이 여기다.

그래서 **약어·외래 용어가 내레이션에 처음 나오는 구간에는 화면에 작은 주석 카드를 붙인다.**

```
LLM  Large Language Model
대규모 언어 모델 — 다음에 올 말을 확률로 골라 문장을 만드는 AI
```

| | |
|---|---|
| 형식 | **원어 약자(큰 글자) · 영문 원문(작게) · 우리말 뜻 + 한 줄 설명** |
| 위치 | **상단이나 도식 옆.** 하단은 자막 자리다 — 겹치면 둘 다 못 읽는다 |
| 크기 | 본문보다 작게(2.3vh / 1.8vh / 1.9vh 기준) — **읽고 싶은 사람만 읽는 각주**이지 주인공이 아니다 |
| 등장 시각 | 내레이션이 그 용어를 **처음 말하는 시각**(`tterm` params 로 넘긴다) |
| 몇 개 | **회차당 2~3개까지.** 용어가 나올 때마다 붙이면 화면이 각주장이 된다 — 회차의 핵심 용어만 |
| 지속 | 그 구간 내내 남긴다(깜빡 사라지면 못 읽는다) |

구현은 `templates/termnote.css` 를 회차 도식 html 의 `<style>` 에 복사해 넣는다.
**공용 `motion/_base.css` 는 수정하지 않는다** — 이미 만든 회차의 렌더가 바뀐다.

우리말로 굳어진 말(프롬프트·클라우드·서버)은 주석이 필요 없다. **철자를 모르면 검색이
불가능한 것**(LLM·API·CoT·ETF·DSR·ISMS)이 대상이다.

### 재미 — 개그가 아니라 "다음이 궁금한 상태"를 유지하는 장치

5분 개념강좌의 재미는 웃기는 것이 아니라 **시청자가 스스로 알아채는 쾌감**이다. 대본을 쓸 때
회차마다 아래에서 **3~4개**를 심는다(전부 넣으면 산만하다 — 차분한 톤과 충돌하지 않는 선에서,
회차 전반에 고르게 배치한다. 한 구간에 장치가 하나도 없으면 그 구간이 처지는 신호다).

| 장치 | 무엇 | 실전 예 |
|---|---|---|
| 구체적 인물·장면 | 추상 개념을 이름 있는 대상에 얹는다 | "사용자 김민준" 카드가 한 줄에 지워짐 — "리소스 삭제"보다 백 배 세다 |
| 회수(페이오프) | 훅에서 심은 것을 끝에서 시청자가 **스스로 읽게** 돌려준다 | 오프닝의 `DELETE` 를 엔딩에서 `GET → 404` 로 — "지웠으니 없다"를 시청자가 알아챈다 |
| 맞혀보기 | 답을 말하기 전에 시청자에게 먼저 맞히게 한다 — 참여가 최고의 재미다 | "다음 단어, 여러분 머릿속에도 떠올랐죠 — 맞습니다, 겠습니다" (work5min-01 엔딩) |
| 반문·자문자답 | 시청자가 막 떠올릴 질문을 먼저 던진다 | "그럼 지우라는 말은 어디에 쓸까요?" → 다음 챕터가 답 |
| 업무 상황극 | 개념이 작동하는 회사 장면 한 컷을 구체적으로 | "퇴근 인사, 정중하게 써 줘"가 입력되는 순간 안에서 벌어지는 일 |
| 일상 비유 | 개념을 이미 아는 경험에 접붙인다 | 클라우드 = 집 비유(땅만 빌리기/몸만 들어가기), 전기 요금 비유 |
| 통념 뒤집기 | "다들 이렇게 알지만 사실은"을 그림으로 | "클라우드는 하늘에 없다 — 실체는 이 건물" |
| 반전 수치 | 검증된 숫자 하나를 예상을 깨는 방식으로 세운다 | "다이얼이 천칠백오십억 개" — 숫자 자체가 장면이 된다 (facts.md 근거 필수) |
| 위트 한 줄 | 내레이션에 가벼운 숨 하나 | "아주 잘 관리되는, 남의 컴퓨터요" — 회차당 1~2번까지만 |

재미의 반대는 지루함이 아니라 **예측 가능함**이다 — 시청자가 다음 문장을 맞힐 수 있으면
그 구간은 다시 쓴다. 단, 유머로 사실을 비틀지 않는다(아래 자료조사 규율). 깊이와 재미는
경쟁하지 않는다 — **가장 좋은 재미 장치는 정확한 지식이 반전으로 서는 순간**이다(반전 수치·
통념 뒤집기·맞혀보기가 그 자리다).

### 자료조사 — 최신·정확한 수치는 인터넷에서 확인하고 출처를 남긴다

강좌 주제(경제·법률·생활·테크)는 저장소에 근거가 없는 **세상 지식**이다. develop-video 의
"근거 있는 문구만 쓴다" 원칙을 이렇게 잇는다:

- **내레이션에 수치·연도·제도·순위가 들어가면 웹 검색으로 확인한다** — 특히 바뀌는 것들
  (금리·세율·공제 한도·법 개정·서비스 요금제)은 아는 것 같아도 검색한다. 조사 시점 기준으로
  최신인지 본다.
- 확인한 사실은 **회차 폴더의 `facts.md`** 에 "주장 — 출처 URL — 확인 날짜"로 남긴다
  (lecture-plan.md 의 리서치 표와 같은 형식). 평가 agent 와 미래의 재제작이 이 파일로 검증한다.
- **출처를 못 찾은 수치는 내레이션에서 뺀다** — 뭉뚱그린 표현("크게 늘었다")으로 바꾸거나
  그 문장을 버린다. 그럴듯한 숫자 하나가 강좌 전체의 신뢰를 무너뜨린다.
- 시의성이 강한 값(오늘의 금리 같은)은 숫자를 박지 말고 **구조를 설명한다** — "기준금리가
  3.5%입니다"는 다음 달에 거짓이 되지만 "기준금리가 오르면 대출금리가 따라 오릅니다"는
  계속 참이다. 영상은 업로드 뒤에 고칠 수 없다.

회차 scenes.json 의 `voice`·`render` 블록은 **course.json 을 그대로 복사한다.** 회차마다
손대는 것은 `motion.clips` 뿐이다. 빌드 전에 어긋남을 확인한다:

```bash
python3 -c "
import json,sys
c=json.load(open('tools/video/projects/<강좌id>/course.json'))
e=json.load(open('tools/video/projects/<강좌id>-NN/scenes.json'))
assert e['voice']==c['voice'], '목소리가 강좌 설정과 다르다: %s vs %s'%(e['voice'],c['voice'])
for k,v in c['render'].items():
    assert e['render'].get(k)==v, 'render.%s 가 강좌 설정과 다르다'%k
print('일관성 OK')"
```

빌드·검증·평가는 develop-video 6~9단계 그대로다(프레임 검증·소리 끄고 보기·평가 agent 포함).

### 3. 유튜브 준비물 — 회차가 완성될 때마다

- **챕터 타임스탬프** (설명란에 그대로 붙인다):
  ```bash
  node .claude/skills/develop-lecture/scripts/chapters.js --project <강좌id>-NN
  ```
  scenes.json 과 음성 캐시에서 챕터 카드의 시작 시각을 계산해 `00:00 오프닝` 형식으로 찍는다.
- **제목 초안**: `[강좌명] n강 — 회차 제목` (시리즈 검색성이 좋고 재생목록에서 정렬된다)
- **설명 초안**: 첫 두 줄에 회차 요약(검색 노출 구간) → 챕터 타임스탬프 → 강좌 재생목록 링크 자리
- **자막**: `out/<id>/final/*.srt` 를 업로드에 첨부한다 (화면에도 구워져 있지만 유튜브 자막을
  켜는 시청자를 위해 둘 다)
- **썸네일 후보**: 타이틀 카드 프레임을 뽑는다 —
  ```bash
  ffmpeg -y -ss 2 -i out/<id>/final/<변형>.mp4 -frames:v 1 out/<id>/frames/thumb.png
  ```
  회차마다 같은 구도(타이틀 카드)라 썸네일도 시리즈로 보인다. 더 강한 썸네일이 필요하면
  훅의 절정 프레임을 후보로 함께 뽑아 사용자에게 고르게 한다.

이 준비물(제목·설명·챕터)은 8단계 보고에 함께 싣는다.

## 일관성 점검 — 회차를 내보내기 전에

새 회차와 직전 회차의 **타이틀 카드 프레임을 나란히 뽑아 비교한다** — 색·글꼴·배치가
같은가, 다른 것은 회차 번호와 제목뿐인가. 워터마크 문구·위치도 같아야 한다.
목소리는 위 python3 검사로 이미 잡히지만, 눈으로 한 번 보는 것이 마지막 방어선이다.

## 제작 기록과 계획 노트

develop-video 규약대로 회차마다 `.claude/memory/<강좌id>-NN.md` 를 남기되, 강좌 공통의
결정(색을 왜 이렇게, 골격을 왜 이렇게)은 **1강 기록에만 적고 뒤 회차는 링크한다** —
같은 내용을 회차마다 복붙하면 고칠 때 전부 어긋난다.

**강의 계획 노트가 저장소에 있으면 상태를 갱신한다** — 이 저장소는
`tools/video/lecture-plan.md` (직장인 5분 개념강좌 전체 커리큘럼). 제목 앞 상태 표기를
회차 **착수 시 ⬜ → 🔄**, **완성(평가까지) 시 🔄 → ✅** 로 바꾼다. 같은 강의가 로드맵과
카테고리 목록 양쪽에 있으면 **둘 다** 바꾼다. 회차 주제를 고를 때도 이 노트가 원천이다 —
우선 제작 30강 로드맵의 ⬜ 중 위에서부터 집는다. **로드맵 순서는 제작 순서일 뿐 수강
순서가 아니다** — 회차는 독립이므로(위 "회차는 독립이다" 절) 어느 것을 먼저 만들어도 되고,
시청자도 아무 편이나 먼저 봐도 된다.
